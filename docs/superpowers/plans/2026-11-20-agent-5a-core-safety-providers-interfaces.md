## 1. `:core:screen-model` (Task 1), package `dev.kestrel.screen.model`

The module `core/screen-model` (`kestrel.jvm.library` with the serialization plugin; `api(libs.kotlinx.serialization.json)`). `IntRect.kt`, `ScreenJson.kt`, `ScreenSnapshot.kt` and `ScreenModelTest.kt` move here unchanged, in the same package; `:core:screen` declares `api(project(":core:screen-model"))`.

- `@Serializable enum class ScrollAxis { VERTICAL, HORIZONTAL }`
- `ScreenElement` gets two last constructor parameters: `val tooltip: String? = null`, `val scrollAxis: ScrollAxis? = null` (after `slider`).
- `enum class Region(val label: String)`: `TOP_LEFT("top-left")`, `TOP("top")`, `TOP_RIGHT("top-right")`, `LEFT("left")`, `MIDDLE("middle")`, `RIGHT("right")`, `BOTTOM_LEFT("bottom-left")`, `BOTTOM("bottom")`, `BOTTOM_RIGHT("bottom-right")`; `companion object { fun of(bounds: IntRect, area: IntRect): Region }` (the centre of `bounds` in a 3×3 grid of `area`; a centre outside `area` is clamped to the nearest cell).
- `object ScreenTree`:
  - `fun frontWindow(snapshot: ScreenSnapshot): WindowSummary?` — the active `APPLICATION` window, else the first `APPLICATION` window, else null.
  - `fun appWindows(snapshot: ScreenSnapshot): List<WindowSummary>` — every `APPLICATION` window (both apps in split screen).
  - `fun ancestors(snapshot: ScreenSnapshot, index: Int): List<Int>` — the indices of the element's ancestors, nearest first.
  - `fun insideScrollable(snapshot: ScreenSnapshot, index: Int): Boolean` — an ancestor is `scrollable`.
  - `fun insideVerticalList(snapshot: ScreenSnapshot, index: Int): Boolean` — an ancestor is scrollable and its `scrollAxis` is `VERTICAL`, or null with an `SCROLL_UP`/`SCROLL_DOWN` action or a class name that ends with `RecyclerView`, `ListView` or `ScrollView` (not `HorizontalScrollView`).
  - `fun inToolbar(snapshot: ScreenSnapshot, index: Int): Boolean` — the element or an ancestor has a view ID that holds `toolbar` or `action_bar`.
  - `fun name(element: ScreenElement): String?` — `label`, else `suggestedName`.
  - `fun idName(viewId: String?): String?` — the part after `:id/` (the whole ID when it has none).
  - `fun visibleArea(snapshot: ScreenSnapshot, window: WindowSummary): IntRect` — the window's bounds with the bottom raised to the top of a keyboard that covers its lower half; the signature's and the observation's regions are measured in it, so the keyboard never changes them.
- `object ScreenTitle`:
  - `fun of(snapshot: ScreenSnapshot, window: WindowSummary, appLabel: String?, withRule3: Boolean = true): String?` — D8's rules 1 to 4 (rule 4 skipped when `appLabel` is null; rule 3 skipped when `withRule3` is false). Rules 2 and 3 and a header band read an element's `text`; a rule's title IDs read its text, description or label; rule 4 the window's title. So a fixture puts a header's name in `text`. Trimmed; null when no rule finds one.
- `data class TitleRule(val packageName: String, val titleIds: List<String> = emptyList(), val headerBand: Double? = null)` — `titleIds` are view-ID names (the part after `:id/`); `headerBand` is the top fraction of the window in which the first text outside every scrollable container is the header (for apps without view IDs).
- `object ScreenTitles { val RULES: List<TitleRule>; fun ruleFor(packageName: String?): TitleRule? }` — 5A's entries: Telegram (`org.telegram.messenger`, `org.telegram.messenger.web`, `headerBand = 0.12`) and `:testapp`'s messenger (`dev.kestrel.testapp`, `titleIds = listOf("chat_title")`); the list has the anchor `// sub-project 5B: entries` for 5B and the controller.
- `@Serializable data class SignaturePart(val className: String?, val viewId: String?, val region: Region, val count: Int)`
- `@Serializable data class Signature(val packageName: String?, val windowId: Int?, val windowKind: WindowKind?, val parts: List<SignaturePart>)` with `fun similarity(other: Signature): Double` (weighted Jaccard of the multisets, 1.0 for two empty ones) and `fun sameScreen(other: Signature): Boolean` (same package and window kind, and similarity ≥ 0.8; the window's ID does not count, because Android gives every window instance a new one, so routines compare recorded signatures with `sameScreen` directly). `toString` prints the package's length and the part count only.
- `object ScreenSignature { const val SAME = 0.8; fun of(snapshot: ScreenSnapshot): Signature }` — the front window (`ScreenTree.frontWindow`), its elements outside every scrollable container, `(className, idName(viewId), Region.of(bounds, window.bounds))` counted.
