# Notes for agents

- The design is in [docs/superpowers/specs/2026-11-12-kestrel-design.md](docs/superpowers/specs/2026-11-12-kestrel-design.md), and the plans are in [docs/superpowers/plans/](docs/superpowers/plans/). The progress of the plan that is being carried out is in `.superpowers/sdd/progress.md`, a local file that is not in git.
- The owner's hard rule for every plan, task and fix: no workarounds and no smallest-change fixes. Do things properly and cleanly: clean code, good architecture and modularity are a must, even when that means a big effort or a large change.
- Test only on the `kestrel-api37` emulator (`emulator-5554`). An emulator's serial depends on the order in which emulators start, and `zoran` has had `emulator-5554` too, so use the serial that `scripts\start-emulator.ps1` prints, and check with `adb -s <serial> emu avd name` that it is `kestrel-api37` before you run anything on it. The script starts kestrel-api37 without a window, because the window links Android's clipboard to Windows' clipboard, which makes the clipboard tests unreliable (README); for a plan step in which the owner works in the emulator's window, close it with `scripts\stop-emulator.ps1 -Serial <serial>` and start it with `-Window`, and afterwards close it and start it again without `-Window`; `scripts\a71-agent.ps1` does both itself around the owner's items in the emulator's window. Never use the AVD `zoran` or the Galaxy S23+. Automated checks and investigations may use the Galaxy A71 (`R58N66RVD7Z`) while it is on USB, without the owner, within these limits: no call; no message, except the task suite's own messages to his Telegram's Saved Messages and its e-mails to himself; no change to his accounts, except the suite's calendar events and contacts in his secondary Google account, each removed after its run; every setting put back afterwards; and no words that Kestrel heard in any result. Anything that needs the owner's hands waits for a plan step that names it.
- Run Gradle through `scripts\gradle.ps1`, and stop it with `scripts\gradle.ps1 --stop` when you are done. It refuses every task that installs, uninstalls or runs tests on a device, also by an abbreviated name.
- Run device tests only through `scripts\connected-test.ps1`, `scripts\voice-test.ps1`, `scripts\command-test.ps1` (the instant commands, on the emulator only), `scripts\provider-check.ps1` (the providers' live cases, which call Copilot: only in the owner's session, or against the stand-in of `scripts\hook.ps1 provider-standin`) `scripts\listen-check.ps1` or `scripts\eval.ps1` (`:tools:eval`: the agent's task suite, the multi-turn tasks of the conversations, which `suite --multi-turn` runs apart from the suite with a baseline part of their own, the injection fixtures, their rehearsals and the egress check; the scripted model by default; with `--live`, the owner's default profile in test mode, on kestrel-api37 and the A71 only, never on the S23+, with no ceiling on AI Credits), as each plan says, and install only through `scripts\install.ps1`, which installs the test app of the A71 sessions with `scripts\install.ps1 -TestApp`. PCAPdroid, which the egress check needs on both test devices, is the one app that a script installs otherwise, through `scripts\eval.ps1 egress-setup`; it stays installed, with its API key in the git-ignored `eval\local\`. Before every live series, `:tools:eval` gives Kestrel the evaluation's kept set on the device: the runtime permissions READ_CALENDAR, READ_CONTACTS, WRITE_CONTACTS, READ_SMS, READ_CALL_LOG, READ_MEDIA_IMAGES and READ_MEDIA_VIDEO, and Kestrel's notification access (its listener `dev.kestrel/dev.kestrel.datatools.notifications.KestrelNotificationListener`, given with `cmd notification allow_listener`). It reads each one back (the notification access from the secure setting `enabled_notification_listeners`), stops before any run when one is missing, and records their states in `suite.json`; a task that needs one of them gives it when it is missing, also without a model. By the owner's decisions of 2026-11-24 the kept set stays on both test devices: no restore, task or script takes any of it back, and a device test that needs a part of it off has it given again afterwards (README). Location, phone state and call answering are not in the set and stay as the owner left them. Cold-boot kestrel-api37 with `scripts\cold-boot.ps1 -Serial <serial>` before each long device suite; the gate scripts refuse to start on a kestrel-api37 that has degraded (its sensors HAL above its limit: cold-boot it) or that stays busy for 2 minutes (another job runs there: wait for it, never cold-boot it), by the CPU use of its sensors HAL and of all of Android that they measure there over 10 s, not by the load average (`Assert-EmulatorHealthy` in `scripts\lib\DeviceGuard.ps1`, README). Close kestrel-api37 with `scripts\stop-emulator.ps1 -Serial <serial>` or the scripts that use `Stop-KestrelEmulator` (`scripts\lib\Kestrel.ps1`), which run `adb shell sync` before `adb emu kill`, never with `emu kill` alone, which once cost Kestrel its APK at the next cold boot. The one exception is a kestrel-api37 that does not answer `adb shell`, so that the sync cannot run: only the operator (the owner) closes it, with `emu kill` alone as README says, and an agent stops and reports it; after that close and the cold boot, `pm path dev.kestrel` must name a `base.apk` and the accounts and the profile must be as before, because the close can lose the last install. When Kestrel's APK is gone, after that close or a script's restart (which then stops), no script installs it again: reinstalling is the operator's decision.
- Send a debug hook through `scripts\hook.ps1`, or by hand as `adb shell content call --uri content://dev.kestrel.hooks --method <COMMAND> --extra <name>:<type>:<value>` (`scripts\hook.ps1 ... -PrintCall` prints the call). The hooks have one transport, the debug-only `TestHookProvider`; there is no hook broadcast any more, so `am broadcast` reaches no hook (plan 7G's amendment "The hooks' transport").
- `Get-Adb` and the other helpers exist only after `. scripts\lib\Kestrel.ps1; Use-KestrelToolchain`, so run that in the same command that uses them.
- `scripts\connected-test.ps1` never lets Gradle uninstall Kestrel or clear its data: it passes the Gradle properties for that itself (`$KestrelDataProperties` in `scripts\lib\DeviceGuard.ps1`), accepts only connected test tasks, instrumentation arguments, `-x <task>` and a few flags that change only what Gradle prints and caches, and ends with exit code 1 when Kestrel was uninstalled or installed again during the run, or, on kestrel-api37, when the number of Google accounts or Kestrel's profiles changed, or when the default profile was replaced or its credential deleted. Never run connected tests in another way.
- `scripts\a71-agent.ps1` runs the two sittings of the agent (sub-project 5) on the A71 and kestrel-api37. Its sitting 2, which the owner starts, calls Copilot through `scripts\eval.ps1 run --live`, but live runs no longer need a sitting: `scripts\eval.ps1 --live` runs them by itself; `-DryRun` runs either sitting on kestrel-api37 with the scripted model. Each sitting turns the live session (`scripts\hook.ps1 agent-live`) off at its start, and sitting 2 turns it off again however it ends. The owner wants to be needed as little as possible: before a sitting asks him for anything, it checks whether that is already done. Sitting 1 needs his hands for about 2 minutes (one real touch of the A71's screen), plus 0 to 6 minutes for missing apps from Play, about 4 for Telegram's sign-in on the A71 and about 2 when the A71's Waze has no Home; sitting 2 needs nothing when both devices have a Copilot profile as their default, else about 3 minutes for each device that lacks one (on kestrel-api37, plus about 2 minutes for the restarts that give it its window for the sign-in and take it away again). Telegram runs only on the A71 (it is not signed in on kestrel-api37, and must not be), WhatsApp is skipped on both devices, and Waze is skipped on kestrel-api37, where it does not work.
- kestrel-api37 holds the owner's own Google account and Kestrel's Copilot profile. No script or agent may sign them in, remove them or clear them there, in any step, a stop or a dry run; before and after a run on it, check that `dumpsys account` still counts the same Google accounts and that `scripts\hook.ps1 -Serial <serial> -Command provider-standin` still answers `profile=copilot` with the same `id=` and `credential=present`. `scripts\connected-test.ps1`, `scripts\a71-providers.ps1` and `scripts\eval.ps1` make this check themselves (`Get-OwnerDataState` in `scripts\lib\DeviceGuard.ps1`, and `AccountGuard` in `:tools:eval`), and stop before they start when Kestrel there answers in another form, as an older build does; `scripts\hook.ps1` refuses `provider-delete` there.
- From plan 7C's Task 8 of sub-project 7 on, Kestrel's database on kestrel-api37 (`kestrel.db`) is at version 3. Install there only builds that contain plan 7C, from any worktree: an older build cannot open the database, and the only way back, a destructive fallback, would delete the owner's profile and settings. The same holds for the A71 from the first plan that installs a build with plan 7C there.
- After you change a script, run `scripts\test-scripts.ps1`.
