# Kestrel

Kestrel is a private, standalone copilot and driver of an Android phone, and it also replaces Google's Voice Access on the owner's phone. It keeps the direct commands that Voice Access has, such as "scroll down", "tap Send" or "show numbers", and it adds whole tasks in one sentence, such as "Kestrel, send Ana a Viber message that I'm 10 minutes late". An agent on the phone then performs the task through Android's accessibility service. Today you give Kestrel its tasks by voice. Sub-project 7, which is being built, adds a second channel: a conversation screen where you type. It also turns tasks into conversations: a command can build on the earlier ones, a bigger goal gets a checklist and limits that you set, and past conversations stay on the phone, encrypted, for you to read and continue (design spec, section 1).

> **Status:** early development. Kestrel listens for its name, its own commands, such as "Kestrel, turn off", and commands for the screen, such as "tap Send" or "scroll down", and it runs tasks, such as "Kestrel, turn on hotspot", with an AI model of a provider that you sign in to. Keep test mode on while you try the agent.

## Privacy rules

- Nothing leaves the phone except the traffic to the LLM provider that the owner configures, and the download of the speech and OCR models: when the owner taps Download in the setup checklist, the phone asks the models' own hosts (GitHub, Hugging Face and ModelScope) for the files, so these hosts see the phone's address and which files it downloads, and nothing else. Speech recognition, voice output, OCR and all storage run on the phone, and there is no telemetry of any kind.
- All network traffic goes through one HTTP client with a host allowlist. The models' hosts are on it only for the model download, and the build-time audit allows only the hosts that `audit/rules.txt` names, each with a reason. Every request is written to an encrypted network log that the owner can view and delete.
- A build-time audit fails the build when a dependency is a known telemetry or advertising library, when a licence is not compatible with GPL-3.0, when code outside the network gateway uses network APIs, or when a native library imports socket functions.

The full design is in [docs/superpowers/specs/2026-11-12-kestrel-design.md](docs/superpowers/specs/2026-11-12-kestrel-design.md).

## Installing from a release

Kestrel's releases are on GitHub, at https://github.com/ak800i/kestrel/releases. Each release has the app, `kestrel-<version>.apk`, signed with Kestrel's release key, and the file `kestrel-<version>.apk.sha256` with the app's SHA-256 hash.

1. On the phone, open the latest release in the browser and download `kestrel-<version>.apk`. To check the file on a computer first, download both files, for example with `gh release download v1.0.0 --repo ak800i/kestrel`, and compare `(Get-FileHash kestrel-1.0.0.apk -Algorithm SHA256).Hash.ToLower()` with the first word of `kestrel-1.0.0.apk.sha256`.
2. Open the downloaded file. Android asks you to let your browser install apps; allow it, and install Kestrel. On a Samsung phone, Auto Blocker blocks apps from a browser, so turn it off for the install (Settings > Security and privacy > Auto Blocker) and on again afterwards.
3. Open Kestrel from the launcher, which opens its conversation screen, and tap the banner "Finish setting up Kestrel" there: it opens the setup checklist, below, which leads through the rest. In step 2, choose the voice and tap Download: Kestrel downloads about 780 MB of speech and OCR models, and about 354 MB more for Kokoro, from the models' own hosts, and checks each file against the hash that comes with the app. It downloads only on Wi-Fi unless you turn on "Use mobile data". The screen stays on while the step shows the download. If the download stops, tap Download again, and it goes on where it stopped.
4. In step 3, Android may say that Kestrel's accessibility service is a restricted setting, because Kestrel came from a browser. Then open Settings > Apps > Kestrel, tap the menu (⋮) and "Allow restricted settings", and turn the service on again.

A newer release installs over an older one and keeps Kestrel's data and models. A build that `scripts\install.ps1` installed carries this computer's debug key instead, so a release cannot install over it: uninstall that build first, which deletes Kestrel's data and models.

## Building

Kestrel builds on Windows with PowerShell. You need:

- the JDK that comes with Android Studio, in `C:\Program Files\Android\Android Studio\jbr` (if it is not there, set `JAVA_HOME` to a JDK 21);
- the Android SDK with the `platforms;android-37.0` package, in the folder that `ANDROID_HOME` names (`D:\AndroidVMs\SDK` if the variable is not set).

```powershell
scripts\gradle.ps1 assembleDebug                    # build the app
scripts\gradle.ps1 check                            # unit tests, lint and the privacy audit
scripts\gradle.ps1 :build-logic:convention:check    # tests of the audit itself
```

`check` runs the privacy audit (`kestrelAudit`) for every build variant, so the debug build that the scripts install is audited too.

A release build (`scripts\gradle.ps1 :app:assembleRelease`) is signed only when the variables `KESTREL_KEYSTORE` (the keystore file), `KESTREL_KEYSTORE_PASSWORD`, `KESTREL_KEY_ALIAS` and `KESTREL_KEY_PASSWORD` name a key; otherwise Gradle writes `app-release-unsigned.apk` (design spec, section 17). `scripts\install.ps1 -Serial $serial -Release` sets them to this computer's debug key, builds the release APK and installs it over the debug build, which keeps Kestrel's data; the release build has no test hooks, so `scripts\install.ps1 -Serial $serial` puts the debug build back afterwards.

The first build downloads sherpa-onnx's Android library (39 MB), which contains the speech engines, from sherpa-onnx's GitHub release. Gradle checks its SHA-256 hash against `gradle/verification-metadata.xml`. The library contains its own copy of ONNX Runtime, so a new version of sherpa-onnx needs a new audit of that copy (`audit/rules.txt`) and a new hash.

`scripts\test-scripts.ps1` tests the PowerShell scripts with Pester in Windows PowerShell 5.1 and in PowerShell 7, and checks them with PSScriptAnalyzer; the comment at its top lists the modules that it needs.

Gradle and the Kotlin compiler keep running in the background between builds. During a build they use about 3 GB and 2 GB of memory. They stop by themselves 15 minutes after the last build, and `scripts\gradle.ps1 --stop` stops them at once. Gradle runs them on Java 21, as `gradle/gradle-daemon-jvm.properties` asks, so a Gradle that you start from another JDK, such as the one that `JAVA_HOME` names, uses the same processes as `scripts\gradle.ps1`, as long as Android Studio's JDK is the only Java 21 on the computer.

To open the project in Android Studio, use Android Studio Rabbit 2 (2026.2.2) or newer, which supports version 9.5 of the Android Gradle plugin.

## Releasing

A release is a tag `v<version>`, such as `v1.0.0`, whose version equals the app's `versionName` in `app/build.gradle.kts` (design spec, section 17). The workflow `.github/workflows/release.yml` runs for every pushed tag that starts with `v`: it runs CI's checks (the audit's own tests, the unit tests, lint and the privacy audit), decodes the release key from the repository's secrets into the runner's temporary folder, builds the signed release APK, refuses an APK whose version differs from the tag's, that carries a debug key, or whose only signer is not the release key (by its certificate's SHA-256 digest, which the workflow pins), and creates a GitHub release with `kestrel-<version>.apk` and `kestrel-<version>.apk.sha256`. A tag with a hyphen, such as `v1.0.0-rc.1`, makes a pre-release.

The release key is in the repository's four secrets: `KESTREL_KEYSTORE_BASE64` (the PKCS12 keystore in base64), `KESTREL_KEYSTORE_PASSWORD`, `KESTREL_KEY_ALIAS` and `KESTREL_KEY_PASSWORD`. Outside GitHub, it is only in `%LOCALAPPDATA%\Kestrel\release-key` on the owner's computer, with its password protected for his Windows account, and in his own backup; it is never committed. Without the same key, a later release cannot install over an earlier one.

The release checklist:

1. CI passes on `main`.
2. On `kestrel-api37`, `scripts\install.ps1 -Serial $serial -Release` installs the release build, signed with this computer's debug key. Open the setup checklist, check that step 2 is done, and put the debug build back with `scripts\install.ps1 -Serial $serial`.
3. For a new version, raise `versionCode` and `versionName` in `app/build.gradle.kts`, and commit.
4. Tag and push, such as `git tag -a v1.0.0 -m "Kestrel 1.0.0"` and `git push origin v1.0.0`, and follow the workflow with `gh run watch`.
5. Check the release: `gh release download v1.0.0 --repo ak800i/kestrel --dir <folder>`, compare the APK's SHA-256 with the `.sha256` file as above, and check with the SDK's `apksigner verify --print-certs` that it has one signer, whose certificate's SHA-256 digest is `ad26dda70846e874d1624783c7983b09f209301c00aa92c157d46571c16003f5`, the digest that `release.yml` checks too.

## Testing on a device

Kestrel is tested only on the `kestrel-api37` emulator and on a Galaxy A71. The scripts refuse other devices. An emulator's serial can pass to another emulator that starts after it ended, so the commands with which the scripts read and change settings check, in the same `adb shell` call, that the device is still the one that the script accepted. Run the device tests with `connected-test.ps1` and install with `install.ps1`: `gradle.ps1` refuses every task that installs, uninstalls or runs tests on a device, also by an abbreviated name such as `cDAT`, whatever `ANDROID_SERIAL` says, and it hides every device from Gradle.

```powershell
scripts\create-avd.ps1                    # once: installs Android 17 and creates kestrel-api37
$serial = scripts\start-emulator.ps1      # starts the emulator without a window and prints its adb serial (-Window: with one)
scripts\cold-boot.ps1 -Serial $serial     # before each long device suite: a cold boot, with the owner's data checked around it
scripts\connected-test.ps1 -Serial $serial :core:privacy:connectedDebugAndroidTest :core:voice:connectedDebugAndroidTest :app:connectedDebugAndroidTest
scripts\command-test.ps1 -Serial $serial  # the instant commands' device tests, on the emulator only, which the line above skips
scripts\install.ps1 -Serial $serial       # runs the privacy audit, then installs the debug build with adb install -r
```

The device tests of the speech engines need the speech models on the device. `scripts\voice-test.ps1 -Serial $serial` installs Kestrel, copies the models with `push-models.ps1 -Kokoro`, so also the optional Kokoro voice, whose tests run too, runs the tests of the package `dev.kestrel.app.voice`, and keeps Kestrel installed, because uninstalling Kestrel deletes the models. It fails when a test was skipped, and it prints the timings and the memory use that the tests measured. One test, `MicCaptureTest#silencedFollowsTheMicrophonesPrivacyToggle`, switches the device's microphone privacy toggle on and off. It skips itself on a phone, where the script also leaves it out, and on an emulator the script switches the toggle off at the end, so that a test process that died cannot leave the microphone silenced. Some of these tests start Kestrel's listening service, switch the emulator's screen off and on with `input keyevent`, turn the emulator's swipe lock screen on (`cmd lock_settings set-disabled false`) and off again, and grant Kestrel the microphone and notification permissions, which stay granted. `ActivationTest` sets the targets of the accessibility shortcut and button and puts them back. Its tile test puts Kestrel's tile first in Quick Settings and opens the panel, and then removes the tile and closes the panel again. It changes the list of tiles, which no script puts back if the test's process dies, so it skips itself on a phone. The lock-screen test unlocks with `wm dismiss-keyguard`, which cannot unlock a PIN, pattern or password, so like the privacy-toggle test it skips itself on a phone, and `voice-test.ps1` leaves all six tests out there (the third is `ActivationTest`'s tile test, above). The fourth, `RefusedReplyTest`, sets Kestrel's app op `TAKE_AUDIO_FOCUS` to `ignore`, so that Android refuses Kestrel's replies, and back to `foreground`, the op's normal mode on Android 17; `default` would still refuse them. The fifth and the sixth, `AssistTest`'s tests of the assist key and of "Kestrel, open settings" with the assistant role, make Kestrel the holder of the assistant role and give the role back to the app that held it, which also puts back the settings `assistant` and `voice_interaction_service`. Before they add the role, they grant Kestrel `READ_SMS` and `READ_CALL_LOG`, because the role grants these to its holder and revokes them when it goes back, which would end Kestrel's process and the tests with it. On an emulator the script turns the lock screen off again at the end, sets the op back to `foreground`, gives the assistant role and those two settings back if they changed, in case a test's process died before it could, and puts `READ_SMS` and `READ_CALL_LOG` back as they were before the run, which the tests cannot do. `MicCaptureTest`'s test of the earbud microphone asks Android for connected earbuds, which would switch a phone's earbuds to their call profile, so it also skips itself on a phone, and `voice-test.ps1` leaves it out there. `connected-test.ps1` runs these tests too, but it puts back none of the above, so after it Kestrel keeps `READ_SMS` and `READ_CALL_LOG` (`adb shell pm revoke dev.kestrel android.permission.READ_SMS`, and the same for `READ_CALL_LOG`, takes them back). They skip themselves when the models are missing, but the models stay on the device after `voice-test.ps1`, so `connected-test.ps1` then runs the voice tests as well, and the models stay on the device after it too, because it never uninstalls Kestrel.

Kestrel is installed with `adb install`, which avoids Android's block on accessibility access for apps from unknown sources. On a Samsung phone, Auto Blocker must be off while USB debugging is in use.

The device tests of `:app` use the fixture screens of `:testapp` (`dev.kestrel.testapp`), a separate app that Gradle installs before the tests. If it was not installed before, `connected-test.ps1` uninstalls it when the tests end, as it does each test APK (`dev.kestrel.test`, and `dev.kestrel.<module>.test` for a library module) that was not installed before. Each test that uses the screen turns Kestrel's accessibility service off and on again. The tests replace the whole list of enabled accessibility services, so other services are off while they run, and Android clears the shortcuts that start those services. `connected-test.ps1` puts the accessibility settings back when the tests end. When the saved list holds Kestrel's service, the script also waits until Android has bound that service again. After a stop or a crash of Kestrel, Android lists the service as crashed. It binds the service again only after the service was turned off and Android has applied that. So the list goes back through `Connect-AccessibilityService` in `scripts\lib\Kestrel.ps1`, as every restore of the accessibility settings does, and the settings that Android changed meanwhile, such as the shortcut and button targets, go back after it. If you stop the tests with Ctrl+C, Windows asks "Terminate batch job (Y/N)?": answer it, and the script puts the settings back before it ends. If Ctrl+C interrupts the script while it puts things back, it prints the command that puts them back by hand. After Ctrl+C, the script ends with exit code 1. Kestrel stays installed after the tests, with its data: `connected-test.ps1` always passes the Gradle properties with which the Android Gradle plugin neither uninstalls Kestrel nor clears its data (`$KestrelDataProperties` in `scripts\lib\DeviceGuard.ps1`), and it accepts only connected test tasks, instrumentation arguments (`-Pandroid.testInstrumentationRunnerArguments.<name>=<value>`), `-x <task>` and a few flags that change only what Gradle prints and caches, such as `--info` and `--no-configuration-cache`. If Kestrel was installed before the tests and is missing after them, or was installed again, which its first-install time shows, the script writes an error that names the loss and ends with exit code 1; the first-install time shows nothing else, such as a `pm clear`. On kestrel-api37 it also compares, before and after the tests, the number of Google accounts in `dumpsys account` and Kestrel's profiles as `scripts\hook.ps1 provider-standin` answers them (the default profile's kind and random ID, whether its credential is stored, and the number of Copilot profiles), so that a profile that was removed or replaced, or a deleted credential, fails the run in the same way; it reads them before it stops Kestrel. When Kestrel there does not answer, for example because it is not installed, the script compares only the accounts; when it answers in another form, as an older build does, the script stops before Gradle runs and says to install the current debug build with `scripts\install.ps1`. The script gives `ANDROID_SERIAL` the caller's value back at the end. At the end it stops Kestrel, which also switches Kestrel's service off. Some tests touch the screen through a virtual touchscreen that Android's `uinput` tool creates: touches from `adb shell input` skip Android's accessibility input filter, while a virtual touchscreen behaves like a finger. On an emulator, `BatteryRestrictionTest` sets Kestrel's app op `RUN_ANY_IN_BACKGROUND` to `ignore`, as the battery setting "Restricted" does, and back to `allow`, the op's normal mode; `default` would leave Kestrel restricted.

The agent's device tests in the package `dev.kestrel.app.agent` run tasks with a scripted model instead of an AI provider; a debug build refuses every other task. `PermissionFlowTest` needs Kestrel's photo and video permissions taken back before the run, and skips itself otherwise, because a test cannot take back one of Kestrel's permissions without ending Kestrel's process: run `foreach ($p in 'READ_MEDIA_IMAGES', 'READ_MEDIA_VIDEO', 'READ_MEDIA_VISUAL_USER_SELECTED') { & $adb -s $serial shell pm revoke dev.kestrel android.permission.$p }` first, after setting `$adb` as the next paragraph shows, and afterwards grant `READ_MEDIA_IMAGES` and `READ_MEDIA_VIDEO` again in the same way with `pm grant`, because they belong to the evaluation's permission set, which stays granted on both test devices (`AGENTS.md`). `AgentEndToEndTest`'s share case needs the opposite, and also skips itself otherwise: run it alone after `& $adb -s $serial shell pm grant dev.kestrel android.permission.READ_MEDIA_IMAGES`, and leave that permission granted. `AgentLocationTest` grants Kestrel the location permission, and `NotificationListenerTest` turns Kestrel's notification access off and on and puts it back. Kestrel's data, such as the agent's memory, survives the run, because `connected-test.ps1` leaves Kestrel installed.

`scripts\eval.ps1` runs `:tools:eval`, the program on this computer that runs the agent's task suite (design spec, section 16.5); it replaced `scripts\task-check.ps1` in sub-project 6. It builds the tool's copy with Gradle when the tool's sources have changed, and stops the Gradle daemon afterwards. `scripts\eval.ps1 run --device $serial --task <name>` runs one task three times, or `--runs` times, and prints one line per run with the task's end, the result of its check on the device and the counts that the debug hooks answered, never screen text; `--results <file>` appends the lines to a file. `suite --device $serial` runs every task of the device into a new folder `eval-results\<device>-<time>\` (`suite.json`, `runs.txt` and `report.json`, which git ignores, because results can hold personal data); `suite --device $serial --resume <results folder>` continues a suite that stopped in the same folder: it keeps each task whose runs all have a line other than `reason=stopped`, runs the rest (only the runs left of the last task that was cut short, or all of that task when HEAD differs from the folder's commit, which it may only in paths that change no run of Kestrel, and then it names the tasks that keep lines of the older commit), and refuses when this call's device or `--live` differ from the folder's, when its runs name another model, when HEAD changed paths that can change a run of Kestrel since the folder's commit (every path but those that `.gitattributes` marks `kestrel-neutral`: `tools\eval`, `eval\baseline.json`, the documentation and Markdown files), or when Kestrel was installed again since the folder's runs (`suite.json` records the installed build: its version, the time of its install, and the commit that the debug build was built from); with `--record-baseline` it records the part of the whole folder once each task has its lines. `--record-baseline` refuses a Kestrel build whose commit differs from HEAD outside those neutral paths, or whose worktree had changes outside them when it was built (the `state` hook answers both), or that names no commit. `injection --device $serial` runs the 14 injection fixtures `inject-01` to `inject-14` and `records-injection`, whose instruction reaches the records of a conversation (design 15.3 of sub-project 7), on the emulator; `suite --device $serial --multi-turn` runs the multi-turn tasks of the conversations apart from the suite, into a folder `eval-results\<device>-multi-turn-<time>\`, and `--resume` continues such a folder only with `--multi-turn` again; `rehearse --device $serial` runs each task's setup, makes its end state without Kestrel's task, checks it and puts the device back; `list` names the tasks. Without `--live`, every run uses the scripted model, so that no request reaches a provider: the six tasks of the design's D3 (`telegram-late`, `hotspot`, `waze-home`, `firefox-wiki`, `telegram-photos` and `read-email`) run as their stand-ins on `:testapp`'s fixtures (`stand-in-messenger-late`, also as `stand-in-messenger-late-reworded`, whose reworded message Kestrel asks to confirm before it types it, `stand-in-messenger-photos`, `stand-in-hotspot`, `stand-in-firefox` and `stand-in-read`; Waze has none), and the injection fixtures with a hostile script; `--dry-run` runs that form once. With `--live`, the runs use the device's default profile, which must be a Copilot profile, in test mode, on `kestrel-api37` and the Galaxy A71 only, never on the S23+. Kestrel's accessibility service must be on; the tool installs a missing Kestrel or `:testapp` with `scripts\install.ps1`, waits until Kestrel listens, turns test mode on, and puts back everything that it changed, also after Ctrl+C, except the evaluation's kept set: before a live series it gives Kestrel its seven data-tool permissions (calendar, contacts with writing, SMS, call log, photos and videos) and its notification access, reads each one back, stops before any run when one is missing and records their states in `suite.json`, and a task gives the ones that it needs when they are missing; by the owner's decisions of 2026-11-24 they stay on both test devices (`AGENTS.md`). It exits with 0 when every run passed or was skipped with a reason, 1 when a run failed or an error stopped it, 2 when it refused before any run (a device, the live gate, the configuration or the command line) and wrote no run line, and 3 when the owner's open conversation with Kestrel stopped it (owner-busy: the evaluation never ends his conversation, writes the runs that it did not run as skipped, and `--resume` runs them); Ctrl+C ends it with Java's own exit code, after it puts the device back. In PowerShell, quote a list, as in `--tasks 'stand-in-hotspot,stand-in-read'`.

The task suite's baseline is in `eval\baseline.json`, a part per device with its commit and model; the multi-turn tasks have parts of their own (`multiTurn`), which `suite --multi-turn --live --record-baseline` records and against which `compare` judges a multi-turn folder, never against the suite's. `scripts\eval.ps1 compare <results folder>` judges a live suite against its device's part: a device fails when its rate is more than 5 percentage points below the baseline's, after 3 more runs of each task that fell (`--rerun --device <serial>`). `scripts\eval.ps1 egress-setup --device <serial>` installs PCAPdroid 2.0.4 once per test device; every live `suite` and `injection` series, and the re-runs of `compare --rerun`, then capture Kestrel's traffic and check it against the device's allowlist (`egress.txt` in the results folder names the hosts and the names that Kestrel's own DNS queries asked for); `run --live` captures nothing. Each call that makes runs in a results folder is one part of its check: its capture is `capture-<stamp>.pcap`, and its result is in `egress.json`. A part that could not be judged, and runs that no capture covers (also after `--resume`), count as unknown and fail the check, as does any connection, or any DNS query of Kestrel's, for a name outside the allowlist; a failed check makes the exit code 1, also for `compare`, which also fails a live report without an egress result, as unknown. `suite --egress` captures a dry run, which must make no connection. The scripts use the adb of the Android SDK. To use the same adb for the commands below, run this in your PowerShell window; it changes only that window's environment:

```powershell
. scripts\lib\Kestrel.ps1; Use-KestrelToolchain; $adb = Get-Adb
```

`start-emulator.ps1` starts the emulator with software rendering (`-gpu swiftshader`), because with the computer's graphics card the emulator slowed down after a few hours of tests. Android inside the emulator still degrades under long test activity: its sensors HAL climbs to 90 % of a CPU, `system_server` blocks for up to 87 s, and apps stop answering, so tests fail for reasons that are not Kestrel's. Cold-boot kestrel-api37 before each long device suite (the `:app` device tests, `voice-test.ps1`, `command-test.ps1`, `listen-check.ps1` and the task suite): run `scripts\cold-boot.ps1 -Serial $serial`, which checks that the serial is kestrel-api37, closes it with `emu kill`, starts it from a cold boot without a window, and checks that the owner's Google accounts and Kestrel's profiles there are as before. A normal start would bring the degraded state back from the emulator's Quick Boot snapshot, and restarting Android inside the emulator is not enough. Before they start on kestrel-api37, `connected-test.ps1`, `voice-test.ps1`, `command-test.ps1`, `listen-check.ps1` and `eval.ps1` read the sensors HAL's CPU use over 10 s and the load average over 5 minutes (`Assert-EmulatorHealthy` in `scripts\lib\DeviceGuard.ps1`), and refuse to start, with the advice to cold-boot, when the HAL uses more than 30 % of one CPU, the load is above 1.5 per CPU, or the two cannot be read. They never check the A71 in this way.

`start-emulator.ps1` starts the emulator without a window (`-no-window`), because only the emulator's window links Android's clipboard to Windows' clipboard. The window does so while the emulator's setting "Enable clipboard sharing" (Extended controls > Settings) is on, and that setting is one for every AVD of this Windows user, `zoran` too; the emulator has no command-line option, feature or AVD setting for it. Android's side of the link sends each clip to Windows on a thread of its own, and the window sends Windows' clip back into Android, so an older clip could replace a newer one a moment later: `ClipboardHookTest` failed so now and then. The tests' clips would also replace your Windows clipboard. For a step in which you work in the emulator's window, close the emulator and start it with `scripts\start-emulator.ps1 -Window`; afterwards close it and start it again without `-Window`. When kestrel-api37 already runs, the script warns if it runs with its window while clipboard sharing is on and `-Window` was not given, or without a window when `-Window` was given. It reads the setting as it is now; turning it on or off in the window applies at once.

### Test hooks

Debug builds contain test hooks that only adb can use (design spec, section 16.1). `scripts\hook.ps1` sends a command and prints the answer, and the comment at the top of the script lists every command. It needs PowerShell 7.3 or newer (`pwsh`), because Windows PowerShell 5.1 drops double quotes from the text that it passes to adb. The screen commands need Kestrel's accessibility service, which you can turn on in Settings > Accessibility, or with adb (this replaces the list of enabled services):

```powershell
& $adb -s $serial shell settings put secure enabled_accessibility_services dev.kestrel/dev.kestrel.app.KestrelAccessibilityService
scripts\hook.ps1 -Serial $serial state                                 # is the screen layer running, and is test mode on?
scripts\hook.ps1 -Serial $serial snapshot -Out $env:TEMP\screen.json   # what Kestrel reads on the screen, as JSON
scripts\hook.ps1 -Serial $serial overlay -Show numbers                 # numbers on the screen's elements
scripts\hook.ps1 -Serial $serial tap -Number 3                         # taps the element with the number 3
scripts\hook.ps1 -Serial $serial test-mode -On true                    # test mode stays on during all testing (design spec, D25)
```

Kestrel's Quick Settings tile starts listening; add it when you edit the Quick Settings panel. Once Kestrel's accessibility service is on, the accessibility button and the accessibility shortcut start it too, when Android's accessibility settings name Kestrel as their target. Each of them toggles between listening and paused, or starts Kestrel when it is off. When Kestrel is the default digital assistant (setup checklist, step 6), the assistant gesture, such as a long press of Home, starts listening and asks "Yes?" for a task; on the lock screen it only starts listening, and you say "Kestrel, ..." after the unlock. The earbuds' assistant button does the same once you pick Kestrel in the chooser that Android opens for it. While Kestrel's accessibility service is off, the first press of the accessibility shortcut only turns the service on, and the next press toggles listening. When you turn the service on, Android adds Kestrel to the accessibility button by itself, and a tap on the button toggles listening. "Kestrel, turn off" or "Stop Kestrel" turns it off. While Kestrel's accessibility service is on, or Kestrel is the default digital assistant, "Kestrel, open settings" opens this app; without either, Android does not let Kestrel open it from the background, so Kestrel says so; a tap on its listening notification, as on Kestrel in the launcher, opens Kestrel's conversation screen, whose Settings open the app. When Android does not bring the app to the front within 5 s, as Android 13 may do while Kestrel is only the default digital assistant, Kestrel says so too, and posts a notification that opens the app with a tap; the Settings of the conversation screen open it too. When Kestrel turns itself off, or cannot start, the feedback bar says why in place of "Off", and so does a notification, whose "Start listening" starts Kestrel again when a new start can help. Listening needs the speech models (setup checklist, step 2), the microphone permission and, for the notification, the notification permission (the setup checklist asks for both). While Kestrel listens, its notification shows whether it listens or is paused, and its Pause or Resume and Stop actions work, also over another app. You can swipe the notification away while the phone is unlocked; Kestrel goes on listening, and the notification comes back when the mode changes. Kestrel stops recording while the screen is off or the phone locked, and goes on after the unlock. With "Use the earbud microphone" on the page "Listening and activation", Kestrel records from connected Bluetooth earbuds instead of the phone's microphone. This switches classic Bluetooth earbuds to their call profile, which makes music sound worse while Kestrel records; when the earbuds go away, the phone's microphone records again. With the permission to read the phone state (setup checklist, step 7), a ringing call makes Kestrel stop speaking and listen only for "answer", "answer on speaker" and "decline", also on the lock screen. It answers and declines through Android's call API when it may answer calls, and otherwise by pressing the phone app's buttons through its accessibility service; it presses "Answer" and "Decline" only in the phone app and in the heads-up notifications, and the in-call screen's buttons only in the phone app, never a button with the same label in another app's window. During the call Kestrel is paused, its notification offers only Stop, the tile and the shortcut choose the mode that comes back after the call, and that mode returns when the call ends. When Android ends Kestrel's process, or the phone restarts, Kestrel comes back in the mode that it had, listening or paused, as soon as its accessibility service connects again or, while Kestrel is the default digital assistant, its assistant service is ready. It stays off when you stopped it yourself (Force stop, "Stop app", or Stop in "Active apps"), unless the phone restarts soon after, because a restart can lose Android's record of the stop. It also stays off when it crashed or stopped answering less than 2 minutes after it came back, or when it ended in another way before it listened again, and a notification then says so. These rules hold on Android 13 too, but there Kestrel also stays off after an update that ended it while it listened. In a debug build the hooks start and drive listening too. A start from a hook needs Kestrel in front, its accessibility service on, or Kestrel as the default digital assistant, because Android lets an app in the background start a microphone service only then.

```powershell
scripts\hook.ps1 -Serial $serial voice -Send toggle                     # starts listening, or pauses it
scripts\hook.ps1 -Serial $serial voice-state                            # the Orchestrator's state, never what was said
scripts\hook.ps1 -Serial $serial voice -Send heard -Text 'Kestrel' -Named   # as if Kestrel had heard its name
scripts\hook.ps1 -Serial $serial voice-clip -Text 'Kestrel, wake up.'   # says the text into a stand-in microphone
scripts\hook.ps1 -Serial $serial voice-clip -Clear                      # gives Kestrel its own microphone back
scripts\hook.ps1 -Serial $serial voice -Send off                        # turns Kestrel off and stores Off, so that it does not come back at its next start
```

`voice-clip` makes Kestrel hear only such clips from its next start until `voice-clip -Clear` or the end of its process. After `voice-clip -Clear`, Kestrel uses its own microphone again from its next start.

`scripts\listen-check.ps1 -Serial $serial` checks the ways in which listening starts without a word, with Kestrel in the background: a tap on "Start listening" in Kestrel's problems notification after Android refused a start through the hook while the accessibility service is off, a tap on the tile while the accessibility service is off, the accessibility shortcut, "Kestrel, open settings" (a transcript that the hook sends) while the service is on, calls on an emulator (below), the return of listening after Android ended Kestrel's process (`am crash`) and, with `-Reboot`, after a reboot, and last, with Kestrel as the default digital assistant and its accessibility service off, a start in the background and the return of listening after `am crash` through the assistant service (without `-Reboot`, it first waits until 2 minutes have passed since the first crash). In every check except the settings check, it also checks in `dumpsys audio` that Android did not silence Kestrel's recording. With `-Reboot`, it reboots a phone with `adb reboot`. A phone with a PIN, pattern or password asks you to unlock it after the reboot. On an emulator, `adb reboot` has crashed or frozen this computer's emulator in about half of the runs, also soon after a cold boot, so the script instead runs `sync` on it, closes it with `adb emu kill`, waits until its qemu process has ended, and starts it again with `scripts\start-emulator.ps1 -ColdBoot`, which must give it the same serial. Start a run with `-Reboot` on an emulator from a cold boot too: run `scripts\cold-boot.ps1 -Serial $serial` first. When the device does not come back (`adb reboot` or `adb emu kill` has not returned within its limit, or the device does not answer within 5 minutes), the script puts nothing back on it: it lists what is left with the commands that put it back by hand, and ends with exit code 1. It needs Kestrel's debug build and the speech models, prints one line for each check that ran and never what Kestrel heard, and needs PowerShell 7.3 or newer, as `hook.ps1` does. While it runs, it grants Kestrel the microphone and notification permissions, replaces the list of enabled accessibility services, sets the target of the accessibility shortcut, opens the notification shade, puts Kestrel's tile first in Quick Settings and opens the panel for the tile check, and makes Kestrel the default digital assistant for the last check; it puts the role and its settings back. The call check runs only on an emulator, whose console places the calls (`gsm call`): a call rings while Kestrel listens in the background, Kestrel shows Ringing and Android does not silence its recording, "decline" declines it and "answer" answers the next one through the call's notification; during that call, with "Commands during a call" on, "Kestrel, mute" with another screen's "Mute" in front (a screen of the debug build) mutes the call with the in-call screen's control and leaves the other screen's switch off, and a second "Kestrel, mute" leaves the call muted; listening comes back after the call; with the permission to answer calls, a plain "answer" leaves the in-call screen behind, and "answer on speaker" brings it to the front with its speaker control on; then a call that wakes the locked screen starts Kestrel's recording, and "decline" declines it. For it the script grants Kestrel the permission to read the phone state, takes away its permission to answer calls until the third call, turns on "Commands during a call" for the mute check, and turns the swipe lock screen on; afterwards it puts these back and deletes its calls from the call log, which it never prints. After a failed run, the phone app may keep a "Missed call" notification for a deleted call; swipe it away. The switch from the earpiece to the speaker is checked on no device: the emulator has no earpiece, the A71 has no SIM card, and the S23+ is not used for tests. It finds the notification's button with `uiautomator dump`, whose file it deletes and never prints, and it expands Kestrel's notification with a swipe when the shade shows it collapsed. When Kestrel's accessibility service was off before the run, Kestrel's notification that the service is off stays afterwards, because the shell cannot remove another app's notification; swipe it away. Afterwards, also when it fails or is interrupted, it turns Kestrel off, closes the panel and puts the rest back. It ends with exit code 1 when a check failed, when it could not put something back (it then prints the command that does it by hand), or after Ctrl+C. Android does not restart an app that crashed twice within 2 minutes, so wait 2 minutes before you run the script again.

The voice corpus is in `corpus\commands.txt`: about 315 English utterances, none of them private, among them the instant commands, speech that must stay bare and dictation, each with what Kestrel's `Requests` should read. `scripts\make-corpus.ps1 -Serial $serial -Voice piper` (or `kokoro`) has Kestrel say each one on the device and copies the clips into `corpus\generated\piper`, and `scripts\voice-eval.ps1 -Serial $serial -Corpus generated -Voice piper -Show` measures the word error rate, the share of utterances that `Requests` reads as intended, the transcription times and Kestrel's memory, and prints each clip that Kestrel misheard; with `-NoBoost` it transcribes without the boost words, to show their effect. Kestrel must be off for it (`scripts\hook.ps1 -Serial $serial voice -Send off`). With `-List checks`, `scripts\make-corpus.ps1` makes the clips of `corpus\checks.txt` too, which the A71's sessions play through the air. Recordings of the owner, if he makes any, go into `corpus\owner\clips`; `scripts\voice-eval.ps1 -Corpus owner` prints only totals for them, never what Kestrel heard. Git ignores both folders of clips. Both scripts need PowerShell 7.3 or newer, as `hook.ps1` does, and they delete their clips on the device at the end.

## Setting up Kestrel

Open Kestrel from the launcher: it opens the conversation screen, which shows the banner "Finish setting up Kestrel" while a step of the setup checklist is to do or needs attention. The banner opens the setup checklist, and the screen's Settings open Kestrel's settings app, whose first entry is the checklist. The checklist says how many of its steps are done (design spec, section 15). Kestrel in the launcher and a tap on Kestrel's listening notification bring back the conversation screen, and close the settings app and the Android screens that the checklist opened above it; open the checklist again from the screen. Whenever Kestrel comes to the front, the checklist reads the state of steps 3 to 7 and 9 from Android, so it shows the changes that you make in Android's settings. Kestrel checks the speech model files for step 2 then too, and also whenever the checklist or the About page opens.

1. Install Kestrel: from a GitHub release, as above, or on a test device with `scripts\install.ps1`. On a Samsung phone, Auto Blocker must be off for the install and while USB debugging is on.
2. Download the speech models. Choose the voice: Kokoro, which sounds more natural and is chosen first on a phone that is fast enough for it (an arm64 phone with about 6 GB of memory or more and a CPU core of at least 2.8 GHz), or Piper, which is always downloaded too and speaks whenever Kokoro cannot. "Use mobile data" is off at first, so Kestrel downloads only on Wi-Fi or another network that does not count its data. Download fetches about 780 MB, and about 354 MB more with Kokoro, from the addresses in the `models\manifest.json` that comes with the app: sherpa-onnx's releases on GitHub, Hugging Face, ModelScope and PaddleOCR's repository on GitHub, which redirect to their own download servers. Kestrel checks each file against the manifest's SHA-256 hash, the step shows the progress and Cancel, and it says why a download stopped; tap Download again to go on. The network log lists each request of the download with its host and size, under the path `/model-download`. A voice that you choose while its files are on the phone becomes Kestrel's voice at once, also after the step is done; otherwise the download that brings its files makes it so. The chosen voice counts from the next time that Kestrel turns on. The first time that Kestrel turns on with Kokoro, it measures how fast Kokoro speaks on the phone; where Kokoro needs longer to say a sentence than the sentence lasts, Piper speaks instead, and the page "Voice and speech" says so. A tap on Kokoro on that page, also while it is chosen, makes Kestrel measure it again the next time that Kestrel turns on. On a test device, `scripts\push-models.ps1 -Serial $serial` copies the models from this computer instead: its first run downloads them into `%LOCALAPPDATA%\Kestrel\models`, checks the same hashes, and copies the files that the phone lacks into Kestrel's folder `Android/data/dev.kestrel/files/models`; with `-Kokoro`, it also copies Kokoro and Kokoro's int8 model, 114 MB, which only a voice device test loads. Uninstalling Kestrel deletes the models from the phone.
3. Turn on Kestrel's accessibility service. The step's button opens Android's accessibility settings. When Android lists the service as on but does not run it, for example after "Stop app", the step asks you to turn it off and on again. When the service goes off while Kestrel runs, for example because you turned it off, a notification says so until the service is on again, and a tap on it opens Android's accessibility settings.
4. Allow the microphone and notifications. The step's button asks Android for both permissions. After you refuse twice, Android no longer asks, and the button opens Kestrel's app settings instead.
5. Allow unrestricted battery use. The step's button opens Kestrel's app settings, where the battery setting is. While Kestrel's battery use is Restricted, the step shows a warning, because Android then stops listening in the background. On a Samsung phone, also add Kestrel to "Never sleeping apps" in the battery settings; the step names it only there.
6. Optionally, make Kestrel the default digital assistant, so that the assistant gesture, such as a long press of Home or the side key, starts Kestrel and lets you say a task. Android does not let an app ask for this role, so the step's button opens Android's default apps, where you pick Kestrel as the digital assistant app.
7. Optionally, let Kestrel answer and decline calls. The step's button asks Android for the permissions to read the phone state and to answer calls. Kestrel reads no phone number and no call log.
8. Sign in to an AI provider and choose the models. This step comes with Kestrel's provider settings.
9. Optionally, give Kestrel notification access, so that the agent can read your notifications when a task needs them; otherwise the agent asks for it the first time. The step's button opens Android's page for Kestrel's notification listener. If Android says that this setting is restricted, open Kestrel's App info, tap the ⋮ menu, then "Allow restricted settings", and try again.
10. Optionally, review the suggested agent-free apps: the step's button opens the Safety page, which lists the installed apps whose names sound like banking or passwords. The step is done once you have reviewed them.
11. Optionally, turn off Voice Access, so that it and Kestrel do not react to the same words. While Voice Access is on, the step's button opens Android's accessibility settings, and the checklist warns while both are on.

The settings app also has these pages:

- **Listening and activation:** what Kestrel does when you unlock the phone (resume the mode from before, always start listening, or stay off), a pause after 30 s without speech, the commands during a call ("Kestrel, hang up", "Kestrel, mute" and "Kestrel, speaker", which count only with the name first, because the other person's voice can come through the speaker; Kestrel transcribes only what starts with its name, so nothing of the call's conversation, and when it misses the name, you say the command again), the earbud microphone, and whether the accessibility service, the shortcut, the button and the assistant role start Kestrel (the tile too, which Android does not report), with a button that opens Android's default apps. Each choice counts at once, also when you leave the page right after it.
- **Safety:** test mode, which is on until you turn it off. While it is on, Kestrel's agent and routines send and share only to your own chats, Telegram's Saved Messages (only in the chat itself: Telegram's share picker stays blocked), WhatsApp's chat with yourself and Viber's My Notes (each only once its rule has been checked on the real app; Telegram's has been), and to your own e-mail addresses; they make no calls and send no SMS (design spec, section 12.7). Kestrel recognises those chats by the screen's structure and by the names that you enter on this page: your e-mail addresses, your name in WhatsApp and the name of your Viber notes chat. Your own instant commands are not limited. Keep test mode on while you test Kestrel. The page also sets the mode, Standard, Relaxed or Full-auto (section 12.3); payments, passwords and protected actions never run by themselves in any mode. Below it are the agent-free apps, which the agent never reads or touches: banking and password apps are on the list, Kestrel suggests more from the apps that you installed, and you can add and remove apps.
- **Memory:** what the agent remembers: aliases and facts ("Kestrel, remember that …"), route notes per app, routines, the counts of finished tasks and the contacts that recent tasks found. You can edit or delete each of them, or delete all memory after a question.
- **Activity log** and **Network log:** what Kestrel did, and every request that it sent, encrypted and kept for 7 days. *Export both logs* writes both logs to a JSON file that you choose, which is the only way the logs leave the phone. *Delete history* wipes both logs after you confirm.
- **Voice and speech:** the voice, Piper or Kokoro (once Kokoro's files are on the phone), and the speed from 0.8 to 1.4. *Try it* speaks a sentence with the choice on the page; while Kestrel listens with that voice and speed, its voice session speaks the sentence, so that no second copy of the voice is loaded. A new voice or speed counts from the next time that Kestrel turns on; when Kokoro does not load, for example because its files are missing, Piper speaks, and the page says so.
- **Instant commands:** "Require verbs", which makes a name alone, such as "Save", do nothing, so that only "tap Save" taps it, and whether numbers go on all elements or only on those without a name; below them, the list of what you can say, which "What can I say?" opens. Each choice counts from the next command.
- **About:** Kestrel's version, the Android version, whether each speech model is ready (the optional Kokoro voice may be "not on the phone"), and the licence texts.

- **Looking closer:** step 2 of the checklist also downloads the three OCR files of `models\manifest.json`, and `scripts\push-models.ps1` copies them on a test device: PP-OCRv5's text detector and its Latin and Cyrillic recognisers, about 21 MB, from ModelScope, Hugging Face and PaddleOCR's repository on GitHub, checked by their SHA-256 hashes. ## Instant commands

While Kestrel listens, you drive the screen by voice without Kestrel's name, as with Voice Access (design spec, section 9 and Appendix A). Say the name of a button to tap it, such as "Send" or "tap Send"; "long press Send" holds it. "Show numbers" puts a number on every element, and then "tap 5", or just "5", taps that element; "hide numbers" removes them. When the numbers change while you say one, Kestrel says "The numbers changed. Say it again.", because the number may name another element by now. "Show labels" shows the name that Kestrel uses for each element, "What is 5?" says the name and the kind of element 5, and "show commands for Send" says what you can do with it. "Show grid" puts numbered squares over the screen for places without an element, "more squares" and "fewer squares" change their size, and "hide grid" removes them. When Kestrel stops listening, because you pause it, a call comes or it turns off, it removes the numbers, the labels and the grid, because only your voice removes them otherwise. You can also scroll ("scroll down", "scroll to bottom", "scroll down on Messages"), swipe ("swipe up", "swipe left on 5", "swipe forwards", "swipe from the left edge"), pinch ("pinch out"), drag ("drag 5 to 9", or "drag 5" and then the place when Kestrel asks "Drag it where?"), check and uncheck ("check Remember me", "switch off"), expand, collapse and dismiss, also notifications in the shade, and move sliders one step ("increment 4", "decrement 4"). A name that you say exactly acts at once when no other element has it, whatever near misses the screen also shows; when two or more elements have that name, Kestrel shows numbers on them only and asks "Which one?". When only a near miss fits, Kestrel acts when the miss is clear, such as "setting" for "Settings", and otherwise asks "Which one?" with its one number, as a confirmation. Answer with the number alone, such as "2", "number 2" or "tap 2": an answer such as "long press 2" ends the question with "Say only the number.", and a number that comes just after the question has ended, within 10 s, does nothing; then say the command again. When nothing matches, it says that it can't find it and shows numbers on every element, so that you can say the number next. A name alone, without a verb, taps only when it clearly names one element: it never asks "Which one?", and it never takes a name that only sounds like what you said, as a command with a verb such as "tap" may. Kestrel ignores other speech without a word, because it may be meant for someone else. "Again" repeats the last command, and "stop" or "cancel" cancels a command while it runs or asks, as a touch does while it asks; while nothing runs, "stop" and "cancel" tap a button with that name. A command that you say while another one runs is dropped, and the feedback bar says "Still busy with the last command." "What can I say?" opens the list of commands on the settings page "Instant commands" and says a short summary.

Before each utterance, Kestrel gives the speech recogniser the names on the screen and a few rare words of the commands, so that it writes them as the screen does. It reads the names from its newest picture of the screen, which it keeps current while it listens; it never uses a password field or what you typed into a field.

The device tests of the instant commands run only through `scripts\command-test.ps1 -Serial $serial`, on the emulator; every other run, such as `connected-test.ps1` above, skips them. The script refuses phones, because the tests change the device's state: Wi-Fi and Bluetooth, the volumes and the ringer mode, Quick Settings' tiles, the lock screen, users, contacts, the call log, screenshots and permissions, and their calls. It ends a call that a test left active, through Android, because Android keeps a call that the emulator's console drops. It puts all of these back at the end, also after a failure or Ctrl+C, except Kestrel's microphone and notification permissions, which stay granted, as after `voice-test.ps1`, because revoking a permission ends Kestrel's process. The text tests also change the clipboard, which the emulator shares with your computer, and put back what it held themselves. The script does not put back Kestrel's own settings: a run leaves Kestrel off, with the default options of the instant commands. It ends with exit code 1 when a test was skipped or something could not be put back. `-Class TouchCommandsTest` runs one class, and `-Class TouchCommandsTest#longPressByLabel` one test.

You can dictate and edit text in any text field, also in Compose apps and on web pages. "Start editing", or "start editing Message" for a field by its name, taps a field and turns dictation on, and so does a field that has the focus: what you say that is not a command is typed at the cursor, with the punctuation that you say ("hello comma how are you question mark" types "Hello, how are you?"), and "capital p one two three" types "P123". Kestrel types only the punctuation that you say. "Type X" types X even when it is a command, as in "type delete"; a button's name alone, such as "Send", is typed too, and "tap Send" taps the button. "Stop editing" turns dictation off for that field and hides the keyboard. You can move the cursor ("go to the end", "move after tomorrow", "left three characters", "right two words"), select ("select tomorrow", "select the next two words", "select all", "unselect"), delete ("delete", which deletes the selection or the word before the cursor, "delete three words", "delete from hello to world", "delete all"), insert ("insert very before nice"), replace ("replace Monday with Tuesday"), change the case ("capitalize paris", "uppercase nasa") and "format email". "Undo" and "redo" take back and redo Kestrel's own edits while the field still shows them, "new line" starts a line in a field with more than one line, "copy", "cut" and "paste" use the clipboard, "show keyboard" and "hide keyboard" do what they say, "show password" shows a password field's text so that you can check it, and "search for coffee" types into the search field and searches. While a password field has the focus, the feedback bar shows "Typing in a password field." instead of what Kestrel heard. Without a field that has the focus, "delete", "copy" and the other one-word commands tap a button with that name.

## Providers

Kestrel sends its requests to the LLM provider of a profile that you set up (design spec, section 10). The providers that it offers come from OpenClaw's provider manifests at the commit in `catalog/openclaw.lock` (MIT License; see `THIRD_PARTY_NOTICES.md`). `scripts\sync-catalog.ps1` makes a shallow, sparse checkout of OpenClaw's repository at that commit in `build\openclaw\<commit>` and runs the Gradle task `:tools:catalog-sync:syncCatalog`, which writes `catalog/providers.json` and prints how many manifests, providers and models it read; `-Commit <hash>` moves the catalog to another commit and writes that commit into the lock. The script fetches only OpenClaw's repository. `catalog/overrides.json` is kept by hand: the providers and sign-in choices that Kestrel leaves out, each with the reason; the settings of each sign-in choice that Kestrel offers, among them the borrowed sign-ins of GitHub Copilot, xAI and MiniMax, of which only Copilot's is on until you turn the others on, and the links to their providers' terms; the providers that OpenClaw defines in code, such as Bedrock, Vertex and Microsoft Foundry; the local servers; and the prices that the manifests lack, among them Copilot's per-token prices and Google's Gemini prices, each with the day it was copied. The app merges both files from its assets, so a change of the overrides needs no new sync. A unit test checks that `providers.json` names the commit in the lock, and another that every name in the overrides exists.

Kestrel counts the cost of each request on the phone from the tokens that the provider reports and these prices, in GitHub AI Credits, where one credit is one US cent. It counts a model whose price it does not know at $5 per million input tokens and $25 per million output tokens until you type the model's price. For a sign-in or key whose subscription pays for the requests, such as xAI's or MiniMax's sign-in, it counts tokens only.

Credentials are encrypted with their own Android Keystore key, in StrongBox when the phone has it, and are never logged or exported. Only the hosts of your profiles are on the network allowlist; a sign-in's other hosts are allowed only while the sign-in runs.

Kestrel sends each profile's requests in its provider's request style, one of eight (design spec, section 10.3): OpenAI's Chat Completions and Responses, Anthropic Messages, Gemini, Ollama, Bedrock Converse, Vertex, and Azure OpenAI with Microsoft Foundry. It streams the answer from most providers and calls Bedrock, Ollama and Claude on Vertex without streaming, and it always works with one complete answer, keeping the reasoning data that a provider needs on the next request. For a model that handles tool calls badly, it asks for a JSON action instead of a tool call. The tests of the request styles use answers written from each provider's documented format, under `core/providers/src/test/resources/fixtures/`, and a local mock server, so no test sends a request to a provider.

A profile signs in with an API key; with a device code (GitHub Copilot, xAI and MiniMax: the page shows a code, and you approve it in a browser on any device); with a browser sign-in in a Custom Tab (the ChatGPT plan, through OpenAI's Sign in with ChatGPT for open-source apps, and OpenRouter), which redirects to a temporary server on the phone's loopback address; with an imported credential (Bedrock's keys, or a Vertex service-account file, of which Kestrel keeps only the four fields that it needs); or with a server address (Ollama, LM Studio and the other local servers). Its results go into `corpus\owner`, which git ignores.
