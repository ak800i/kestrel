# Kestrel

Kestrel is a private, voice-first assistant for Android. It is meant to replace Google's Voice Access on the owner's phone. It keeps the direct commands that Voice Access has, such as "scroll down", "tap Send" or "show numbers", and it adds whole tasks in one sentence, such as "Kestrel, send Ana a Viber message that I'm 10 minutes late". An agent on the phone then performs the task through Android's accessibility service.

> **Status:** early development. Kestrel listens for its name, its own commands, such as "Kestrel, turn off", and commands for the screen, such as "tap Send" or "scroll down", but it cannot run tasks yet.

## Privacy rules

- Nothing leaves the phone except the traffic to the LLM provider that the owner configures. Speech recognition, voice output, OCR and all storage run on the phone, and there is no telemetry of any kind.
- All network traffic goes through one HTTP client with a host allowlist. Every request is written to an encrypted network log that the owner can view and delete.
- A build-time audit fails the build when a dependency is a known telemetry or advertising library, when a licence is not compatible with GPL-3.0, when code outside the network gateway uses network APIs, or when a native library imports socket functions.

The full design is in [docs/superpowers/specs/2026-11-12-kestrel-design.md](docs/superpowers/specs/2026-11-12-kestrel-design.md).

## Building

Kestrel builds on Windows with PowerShell. You need:

- the JDK that comes with Android Studio, in `C:\Program Files\Android\Android Studio\jbr` (if it is not there, set `JAVA_HOME` to a JDK 21);
- the Android SDK with the `platforms;android-37.0` package, in the folder that `ANDROID_HOME` names (`D:\AndroidVMs\SDK` if the variable is not set).

```powershell
scripts\gradle.ps1 assembleDebug                    # build the app
scripts\gradle.ps1 check                            # unit tests, lint and the privacy audit
scripts\gradle.ps1 :build-logic:convention:check    # tests of the audit itself
```

`check` runs the privacy audit (`kestrelAudit`) for every build variant, so the debug build that the scripts install is audited too.

The first build downloads sherpa-onnx's Android library (39 MB), which contains the speech engines, from sherpa-onnx's GitHub release. Gradle checks its SHA-256 hash against `gradle/verification-metadata.xml`. The library contains its own copy of ONNX Runtime, so a new version of sherpa-onnx needs a new audit of that copy (`audit/rules.txt`) and a new hash.

`scripts\test-scripts.ps1` tests the PowerShell scripts with Pester in Windows PowerShell 5.1 and in PowerShell 7, and checks them with PSScriptAnalyzer; the comment at its top lists the modules that it needs.

Gradle and the Kotlin compiler keep running in the background between builds. During a build they use about 3 GB and 2 GB of memory. They stop by themselves 15 minutes after the last build, and `scripts\gradle.ps1 --stop` stops them at once. Gradle runs them on Java 21, as `gradle/gradle-daemon-jvm.properties` asks, so a Gradle that you start from another JDK, such as the one that `JAVA_HOME` names, uses the same processes as `scripts\gradle.ps1`, as long as Android Studio's JDK is the only Java 21 on the computer.

To open the project in Android Studio, use Android Studio Rabbit 2 (2026.2.2) or newer, which supports version 9.5 of the Android Gradle plugin.

## Testing on a device

Kestrel is tested only on the `kestrel-api37` emulator and on a Galaxy A71. The scripts refuse other devices. An emulator's serial can pass to another emulator that starts after it ended, so the commands with which the scripts read and change settings check, in the same `adb shell` call, that the device is still the one that the script accepted. Run the device tests with `connected-test.ps1` and install with `install.ps1`: `gradle.ps1` refuses tasks that install or test on a device unless the environment variable `ANDROID_SERIAL` names test devices, and for other tasks it hides every device from Gradle.

```powershell
scripts\create-avd.ps1                    # once: installs Android 17 and creates kestrel-api37
$serial = scripts\start-emulator.ps1      # starts the emulator and prints its adb serial
scripts\connected-test.ps1 -Serial $serial :core:privacy:connectedDebugAndroidTest :core:voice:connectedDebugAndroidTest :app:connectedDebugAndroidTest
scripts\command-test.ps1 -Serial $serial  # the instant commands' device tests, on the emulator only, which the line above skips
scripts\install.ps1 -Serial $serial       # runs the privacy audit, then installs the debug build with adb install -r
```

The device tests of the speech engines need the speech models on the device. `scripts\voice-test.ps1 -Serial $serial` installs Kestrel, copies the models with `push-models.ps1 -Kokoro`, so also the optional Kokoro voice, whose tests run too, runs the tests of the package `dev.kestrel.app.voice`, and keeps Kestrel and its test APK installed, because uninstalling Kestrel deletes the models. It fails when a test was skipped, and it prints the timings and the memory use that the tests measured. One test, `MicCaptureTest#silencedFollowsTheMicrophonesPrivacyToggle`, switches the device's microphone privacy toggle on and off. It skips itself on a phone, where the script also leaves it out, and on an emulator the script switches the toggle off at the end, so that a test process that died cannot leave the microphone silenced. Some of these tests start Kestrel's listening service, switch the emulator's screen off and on with `input keyevent`, turn the emulator's swipe lock screen on (`cmd lock_settings set-disabled false`) and off again, and grant Kestrel the microphone and notification permissions, which stay granted. `ActivationTest` sets the targets of the accessibility shortcut and button and puts them back. Its tile test puts Kestrel's tile first in Quick Settings and opens the panel, and then removes the tile and closes the panel again. It changes the list of tiles, which no script puts back if the test's process dies, so it skips itself on a phone. The lock-screen test unlocks with `wm dismiss-keyguard`, which cannot unlock a PIN, pattern or password, so like the privacy-toggle test it skips itself on a phone, and `voice-test.ps1` leaves all six tests out there (the third is `ActivationTest`'s tile test, above). The fourth, `RefusedReplyTest`, sets Kestrel's app op `TAKE_AUDIO_FOCUS` to `ignore`, so that Android refuses Kestrel's replies, and back to `foreground`, the op's normal mode on Android 17; `default` would still refuse them. The fifth and the sixth, `AssistTest`'s tests of the assist key and of "Kestrel, open settings" with the assistant role, make Kestrel the holder of the assistant role and give the role back to the app that held it, which also puts back the settings `assistant` and `voice_interaction_service`. On an emulator the script turns the lock screen off again at the end, sets the op back to `foreground`, and gives the assistant role and those two settings back if they changed, in case a test's process died before it could. `MicCaptureTest`'s test of the earbud microphone asks Android for connected earbuds, which would switch a phone's earbuds to their call profile, so it also skips itself on a phone, and `voice-test.ps1` leaves it out there. `connected-test.ps1` runs these tests too. They skip themselves when the models are missing, but the models stay on the device after `voice-test.ps1`, so `connected-test.ps1` then runs the voice tests as well; at the end Gradle uninstalls Kestrel, which deletes the models.

Kestrel is installed with `adb install`, which avoids Android's block on accessibility access for apps from unknown sources. On a Samsung phone, Auto Blocker must be off while USB debugging is in use.

The device tests of `:app` use the fixture screens of `:testapp` (`dev.kestrel.testapp`), a separate app that Gradle installs before the tests. If it was not installed before, `connected-test.ps1` uninstalls it when the tests end. Each test that uses the screen turns Kestrel's accessibility service off and on again. The tests replace the whole list of enabled accessibility services, so other services are off while they run, and Android clears the shortcuts that start those services. `connected-test.ps1` puts the accessibility settings back when the tests end. If you stop the tests with Ctrl+C, Windows asks "Terminate batch job (Y/N)?": answer it, and the script puts the settings back before it ends. If Ctrl+C interrupts the script while it puts things back, it prints the command that puts them back by hand. After Ctrl+C, the script ends with exit code 1. After the tests, Gradle uninstalls Kestrel and its test APK, which also switches Kestrel's service off. A run stopped with Ctrl+C during the tests leaves both installed; `connected-test.ps1` stops Kestrel, and you can remove them with `& $adb -s $serial uninstall dev.kestrel.test` and `& $adb -s $serial uninstall dev.kestrel`, after setting `$adb` as the next paragraph shows. Some tests touch the screen through a virtual touchscreen that Android's `uinput` tool creates: touches from `adb shell input` skip Android's accessibility input filter, while a virtual touchscreen behaves like a finger. On an emulator, `BatteryRestrictionTest` sets Kestrel's app op `RUN_ANY_IN_BACKGROUND` to `ignore`, as the battery setting "Restricted" does, and back to `allow`, the op's normal mode; `default` would leave Kestrel restricted.

The scripts use the adb of the Android SDK. To use the same adb for the commands below, run this in your PowerShell window; it changes only that window's environment:

```powershell
. scripts\lib\Kestrel.ps1; Use-KestrelToolchain; $adb = Get-Adb
```

`start-emulator.ps1` starts the emulator with software rendering (`-gpu swiftshader`), because with the computer's graphics card the emulator slowed down after a few hours of tests. Android inside the emulator can still slow down after many hours of tests. If the device tests become slow, or Android restarts while they run, restart the emulator with a cold boot: run `& $adb -s $serial emu kill`, wait until the emulator has closed, and then run `$serial = scripts\start-emulator.ps1 -ColdBoot`. A normal start would bring the slow state back from the emulator's Quick Boot snapshot, and restarting Android inside the emulator is not enough.

### Test hooks

Debug builds contain test hooks that only adb can use (design spec, section 16.1). `scripts\hook.ps1` sends a command and prints the answer, and the comment at the top of the script lists every command. It needs PowerShell 7.3 or newer (`pwsh`), because Windows PowerShell 5.1 drops double quotes from the text that it passes to adb. The screen commands need Kestrel's accessibility service, which you can turn on in Settings > Accessibility, or with adb (this replaces the list of enabled services):

```powershell
& $adb -s $serial shell settings put secure enabled_accessibility_services dev.kestrel/dev.kestrel.app.KestrelAccessibilityService
scripts\hook.ps1 -Serial $serial state                                 # is the screen layer running, and is test mode on?
scripts\hook.ps1 -Serial $serial snapshot -Out $env:TEMP\screen.json   # what Kestrel reads on the screen, as JSON
scripts\hook.ps1 -Serial $serial overlay -Show numbers                 # numbers on the screen's elements
scripts\hook.ps1 -Serial $serial tap -Number 3                         # taps the element with the number 3
scripts\hook.ps1 -Serial $serial test-mode -On true                    # test mode stays on during all testing (design spec, D25)
```

Kestrel's Quick Settings tile starts listening; add it when you edit the Quick Settings panel. Once Kestrel's accessibility service is on, the accessibility button and the accessibility shortcut start it too, when Android's accessibility settings name Kestrel as their target. Each of them toggles between listening and paused, or starts Kestrel when it is off. When Kestrel is the default digital assistant (setup checklist, step 6), the assistant gesture, such as a long press of Home, starts listening and asks "Yes?" for a task; on the lock screen it only starts listening, and you say "Kestrel, ..." after the unlock. The earbuds' assistant button does the same once you pick Kestrel in the chooser that Android opens for it. While Kestrel's accessibility service is off, the first press of the accessibility shortcut only turns the service on, and the next press toggles listening. When you turn the service on, Android adds Kestrel to the accessibility button by itself, and a tap on the button toggles listening. "Kestrel, turn off" or "Stop Kestrel" turns it off. While Kestrel's accessibility service is on, or Kestrel is the default digital assistant, "Kestrel, open settings" opens this app; without either, Android does not let Kestrel open it from the background, so Kestrel says so; a tap on its listening notification, or on Kestrel in the launcher, opens the app. When Android does not bring the app to the front within 5 s, as Android 13 may do while Kestrel is only the default digital assistant, Kestrel says so too, and posts a notification that opens the app with a tap; Kestrel in the launcher opens it too. When Kestrel turns itself off, or cannot start, the feedback bar says why in place of "Off", and so does a notification, whose "Start listening" starts Kestrel again when a new start can help. Listening needs the speech models (`push-models.ps1`), the microphone permission and, for the notification, the notification permission (the setup checklist asks for both). While Kestrel listens, its notification shows whether it listens or is paused, and its Pause or Resume and Stop actions work, also over another app. You can swipe the notification away while the phone is unlocked; Kestrel goes on listening, and the notification comes back when the mode changes. Kestrel stops recording while the screen is off or the phone locked, and goes on after the unlock. With "Use the earbud microphone" on the page "Listening and activation", Kestrel records from connected Bluetooth earbuds instead of the phone's microphone. This switches classic Bluetooth earbuds to their call profile, which makes music sound worse while Kestrel records; when the earbuds go away, the phone's microphone records again. With the permission to read the phone state (setup checklist, step 7), a ringing call makes Kestrel stop speaking and listen only for "answer", "answer on speaker" and "decline", also on the lock screen. It answers and declines through Android's call API when it may answer calls, and otherwise by pressing the phone app's buttons through its accessibility service; it presses "Answer" and "Decline" only in the phone app and in the heads-up notifications, and the in-call screen's buttons only in the phone app, never a button with the same label in another app's window. During the call Kestrel is paused, its notification offers only Stop, the tile and the shortcut choose the mode that comes back after the call, and that mode returns when the call ends. When Android ends Kestrel's process, or the phone restarts, Kestrel comes back in the mode that it had, listening or paused, as soon as its accessibility service connects again or, while Kestrel is the default digital assistant, its assistant service is ready. It stays off when you stopped it yourself (Force stop, "Stop app", or Stop in "Active apps"), unless the phone restarts soon after, because a restart can lose Android's record of the stop. It also stays off when it crashed or stopped answering less than 2 minutes after it came back, or when it ended in another way before it listened again, and a notification then says so. These rules hold on Android 13 too, but there Kestrel also stays off after an update that ended it while it listened. In a debug build the hooks start and drive listening too. A start from a hook needs Kestrel in front, its accessibility service on, or Kestrel as the default digital assistant, because Android lets an app in the background start a microphone service only then.

```powershell
scripts\hook.ps1 -Serial $serial voice -Send toggle                     # starts listening, or pauses it
scripts\hook.ps1 -Serial $serial voice-state                            # the Orchestrator's state, never what was said
scripts\hook.ps1 -Serial $serial voice -Send heard -Text 'Kestrel' -Named   # as if Kestrel had heard its name
scripts\hook.ps1 -Serial $serial voice-clip -Text 'Kestrel, wake up.'   # says the text into a stand-in microphone
scripts\hook.ps1 -Serial $serial voice-clip -Clear                      # gives Kestrel its own microphone back
scripts\hook.ps1 -Serial $serial voice -Send off                        # turns Kestrel off and stores Off, so that it does not come back at its next start
```

`voice-clip` makes Kestrel hear only such clips from its next start until `voice-clip -Clear` or the end of its process. After `voice-clip -Clear`, Kestrel uses its own microphone again from its next start.

`scripts\listen-check.ps1 -Serial $serial` checks the ways in which listening starts without a word, with Kestrel in the background: a tap on "Start listening" in Kestrel's problems notification after Android refused a start through the hook while the accessibility service is off, a tap on the tile while the accessibility service is off, the accessibility shortcut, "Kestrel, open settings" (a transcript that the hook sends) while the service is on, calls on an emulator (below), the return of listening after Android ended Kestrel's process (`am crash`) and, with `-Reboot`, after a reboot, and last, with Kestrel as the default digital assistant and its accessibility service off, a start in the background and the return of listening after `am crash` through the assistant service (without `-Reboot`, it first waits until 2 minutes have passed since the first crash). In every check except the settings check, it also checks in `dumpsys audio` that Android did not silence Kestrel's recording. With `-Reboot`, it reboots a phone with `adb reboot`. A phone with a PIN, pattern or password asks you to unlock it after the reboot. On an emulator, `adb reboot` has crashed or frozen this computer's emulator in about half of the runs, also soon after a cold boot, so the script instead runs `sync` on it, closes it with `adb emu kill`, waits until its qemu process has ended, and starts it again with `scripts\start-emulator.ps1 -ColdBoot`, which must give it the same serial. Start a run with `-Reboot` on an emulator from a cold boot too: run `& $adb -s $serial emu kill`, wait until the emulator has closed, and then run `$serial = scripts\start-emulator.ps1 -ColdBoot`. When the device does not come back (`adb reboot` or `adb emu kill` has not returned within its limit, or the device does not answer within 5 minutes), the script puts nothing back on it: it lists what is left with the commands that put it back by hand, and ends with exit code 1. It needs Kestrel's debug build and the speech models, prints one line for each check that ran and never what Kestrel heard, and needs PowerShell 7.3 or newer, as `hook.ps1` does. While it runs, it grants Kestrel the microphone and notification permissions, replaces the list of enabled accessibility services, sets the target of the accessibility shortcut, opens the notification shade, puts Kestrel's tile first in Quick Settings and opens the panel for the tile check, and makes Kestrel the default digital assistant for the last check; it puts the role and its settings back. The call check runs only on an emulator, whose console places the calls (`gsm call`): a call rings while Kestrel listens in the background, Kestrel shows Ringing and Android does not silence its recording, "decline" declines it and "answer" answers the next one through the call's notification; during that call, with "Commands during a call" on, "Kestrel, mute" with another screen's "Mute" in front (a screen of the debug build) mutes the call with the in-call screen's control and leaves the other screen's switch off, and a second "Kestrel, mute" leaves the call muted; listening comes back after the call; with the permission to answer calls, a plain "answer" leaves the in-call screen behind, and "answer on speaker" brings it to the front with its speaker control on; then a call that wakes the locked screen starts Kestrel's recording, and "decline" declines it. For it the script grants Kestrel the permission to read the phone state, takes away its permission to answer calls until the third call, turns on "Commands during a call" for the mute check, and turns the swipe lock screen on; afterwards it puts these back and deletes its calls from the call log, which it never prints. After a failed run, the phone app may keep a "Missed call" notification for a deleted call; swipe it away. The switch from the earpiece to the speaker is checked on no device: the emulator has no earpiece, the A71 has no SIM card, and the S23+ is not used for tests. It finds the notification's button with `uiautomator dump`, whose file it deletes and never prints, and it expands Kestrel's notification with a swipe when the shade shows it collapsed. When Kestrel's accessibility service was off before the run, Kestrel's notification that the service is off stays afterwards, because the shell cannot remove another app's notification; swipe it away. Afterwards, also when it fails or is interrupted, it turns Kestrel off, closes the panel and puts the rest back. It ends with exit code 1 when a check failed, when it could not put something back (it then prints the command that does it by hand), or after Ctrl+C. Android does not restart an app that crashed twice within 2 minutes, so wait 2 minutes before you run the script again.

The voice corpus is in `corpus\commands.txt`: about 315 English utterances, none of them private, among them the instant commands, speech that must stay bare and dictation, each with what Kestrel's `Requests` should read. `scripts\make-corpus.ps1 -Serial $serial -Voice piper` (or `kokoro`) has Kestrel say each one on the device and copies the clips into `corpus\generated\piper`, and `scripts\voice-eval.ps1 -Serial $serial -Corpus generated -Voice piper -Show` measures the word error rate, the share of utterances that `Requests` reads as intended, the transcription times and Kestrel's memory, and prints each clip that Kestrel misheard; with `-NoBoost` it transcribes without the boost words, to show their effect. Kestrel must be off for it (`scripts\hook.ps1 -Serial $serial voice -Send off`). The owner's recordings, which the step `recordings` of `scripts\a71-commands.ps1` makes, go into `corpus\owner\clips`; `scripts\voice-eval.ps1 -Corpus owner` prints only totals for them, never what Kestrel heard. Git ignores both folders of clips. Both scripts need PowerShell 7.3 or newer, as `hook.ps1` does, and they delete their clips on the device at the end.

Release builds do not contain the hooks, and the privacy audit fails a release build that does.

### Spikes

These scripts check assumptions of the design on a test device (design spec, section 19). They need Kestrel's debug build, and the results are in section 19.1 of the design spec.

- `scripts\spike-s1.ps1 -Serial $serial` checks whether Kestrel can read the location while another app is in front, the one part of spike S1 that still uses the debug hooks. It prints whether a location came, never the place. While it runs, it grants Kestrel the location permissions, changes the accessibility services, turns location on, lets the shell set mock locations and replaces the fused location provider with a test provider. Afterwards, also when the script fails or is interrupted, it puts all of this back as it was before, and it revokes only the permissions that Kestrel did not have. Before it turns the accessibility service on, it turns Kestrel off, and Kestrel stays off afterwards. Android may still keep the made-up place as the last known location, until the device gets a real location or restarts. If it cannot put something back, also because Ctrl+C interrupted it while it put things back, it says at the end what is left and the command that puts it back, and it ends with exit code 1. After Ctrl+C, it also ends with exit code 1.
- `scripts\spike-s4.ps1 -Serial $serial -Browser chrome, firefox` serves `scripts\spike-s4\page.html` from this computer with the JDK's `jwebserver`, opens it in each browser through `adb reverse`, and prints which of the page's elements Kestrel reads and whether Kestrel can type into its text fields. A browser that is not installed is skipped. The script taps through the browsers' first-run screens that it knows, and otherwise asks you to finish them. While it runs, it replaces the enabled accessibility services with Kestrel's, adds an `adb reverse` rule, runs `jwebserver` on this computer and stops each browser after its checks, also one that was running before. Before it turns the accessibility service on, it turns Kestrel off, and Kestrel stays off afterwards. Afterwards, also when it fails or is interrupted, it puts back the accessibility settings, removes the rule and stops `jwebserver`. It leaves on purpose Firefox, which the plan installs on the emulator for this spike, and in the browsers the tabs and the history of the page and the choices of their first-run screens. If it cannot put something back, also because Ctrl+C interrupted it while it put things back, it says at the end what is left and how to put it back, and it ends with exit code 1. After Ctrl+C, or when Kestrel cannot scroll in a browser, it also ends with exit code 1.
- `scripts\spike-s7.ps1 -Serial $serial` pushes a file of random bytes into Kestrel's external files folder with `adb push`, where the model files will live, and checks that Kestrel reads the same bytes. While it runs, it creates folders in Kestrel's external files folder, also `Android/data/dev.kestrel` and its `files` folder if they are not there, and it writes the file in the temporary folder of this computer. It also reinstalls Kestrel with `adb install -r`, which stays, as after `scripts\install.ps1`. Afterwards, also when it fails or is interrupted, it deletes the folders that it created and the file. If it cannot delete something, also because Ctrl+C interrupted it while it deleted things, it says at the end what is left and the command that deletes it, and it ends with exit code 1. After Ctrl+C, it also ends with exit code 1.
- Spike S8, whether sherpa-onnx's own ONNX Runtime and onnxruntime-android work in one process, is the device test `OnnxRuntimeTogetherTest`, which `scripts\voice-test.ps1 -Serial $serial` runs with the other voice tests.

### The A71 session

`scripts\a71-session.ps1 -Serial $serial` takes the owner through the second session on the Galaxy A71, about 4 hours, of which about 65 minutes need your hands or voice and the rest runs while you may leave or stay quiet. It repeats the checks of the voice features that failed or were not valid in the session of 2026-11-17 (design spec, section 19.1), and adds the measures that were missing: the voice device tests, among them the keyword spotter's three settings with generated speech and Kokoro's fp32 and int8 models side by side; `listen-check.ps1 -Reboot`, after a check of the last byte of `dumpsys accessibility`; Android's and Samsung's battery rules, with Android's record of the listening service every 5 s; the shortcut, the button and the tile; "Kestrel, open settings" with only the assistant role, and the restore after a crash; the route of the earbud microphone; "Hey Kestrel" and about 1.5 minutes of played speech without a keyword with each of the three settings of the keyword spotter, after which the script names the setting that its rule keeps; the owner's voice with Kestrel, with interruptions after pauses of about 1, 1.5 and 2 s; Kestrel's memory categories with Piper and Kokoro, and a cold start through the tile; and three battery measures of 30 minutes (a quiet room, a task every 5 minutes from this computer's speaker, and room talk), which give "% per hour = baseline + cost per transcribed minute × minutes". Every time comes from the phone: Kestrel records when it was started, opened its session, heard the end of speech, reacted and turned itself off, and the script reads these times through `hook.ps1 voice-times`; no measure counts from your Enter. Each prompt says what you do and what the phone shows or does not show, such as "Say "Hey Kestrel" once. Kestrel should say "Yes?" and wait; the script ends the wait itself." The session and `scripts\a71-commands.ps1` make one sitting of about 6 hours, of which about 2.5 to 3 hours need you: `a71-commands.ps1` first, with all its steps, so that you record the voice corpus while you are fresh, and then `a71-session.ps1` with all its steps; you may split the sitting into two at the boundary between the scripts. The session's first step installs Kestrel, copies the models with both of Kokoro's models, which `a71-commands.ps1` does not copy, and grants Kestrel the microphone and notification permissions, which stay granted afterwards. It asks before each step, and before it first reads the device; `s` skips, `q` stops. `-Step` runs only the named steps. It refuses every device but the A71 and `kestrel-api37`. The results go into `corpus\owner\session-<time>.txt`, which git ignores, and neither the results nor the console ever hold what Kestrel heard: the hooks answer only counts, times, kinds and device types. While the session runs, the phone's screen stays on while it is plugged in. Afterwards, also when a step fails or Ctrl+C stops it, the script puts back Kestrel's mode Off, the hooks' slow task, the keyword spotter's setting, the setting "Stay awake", the assistant role and its settings, Kestrel's battery restriction (as `allow` or `ignore`, never as `default`, which Android counts as restricted), Kestrel's voice, the accessibility settings, the screen's timeout and the battery's state. The battery measures reset the phone's battery statistics, which cannot be put back, and the script asks you to turn "Use the earbud microphone" off again if you turned it on. `-DryRun` runs the session on `kestrel-api37` without the owner, to try a change of the script; it answers its own questions, sends what the owner would say through the voice hook, taps Kestrel's tile through SystemUI, also for the cold start, plays no sound, skips what needs the owner's hands otherwise, runs `listen-check.ps1` without `-Reboot`, skips the voice device tests, and shortens the waits and the battery measures to a minute. It needs PowerShell 7.3 or newer, as `hook.ps1` does.

The session's measurements, with the targets of the design spec (section 5.3):

| Measure | Target | Galaxy A71 |
|---|---|---|
| Transcription time of a command | at most 4 s | met on 2026-11-17: a median of 272 ms with Piper's generated clips (90th percentile 463 ms, longest 817 ms) and 257 ms with Kokoro's (longest 732 ms) |
| Kestrel's memory while it listens (PSS) | at most 2 GB | met with Piper on 2026-11-17: 976 to 1150 MB while Kestrel listened, at most 1704 MB while the eval hook transcribed the corpus, with Kestrel off; Kokoro's fp32 model reached 2049 MB at its first start, because memory of the earlier sessions stayed in the process |
| Battery use while listening | at most 2 % per hour | not measured for a typical case yet: 3.69 % per hour on 2026-11-17 is a worst case, with the screen on and 30 minutes of room talk that Kestrel transcribed |

## Setting up Kestrel

Open Kestrel from the launcher. The first entry of its settings app is the setup checklist, which says how many of its steps are done (design spec, section 15). Whenever Kestrel comes to the front, the checklist reads the state of steps 3 to 7 and 9 from Android, so it shows the changes that you make in Android's settings. Kestrel checks the speech model files for step 2 then too, and also whenever the checklist or the About page opens.

1. Install Kestrel with `scripts\install.ps1`. On a Samsung phone, Auto Blocker must be off while USB debugging is on.
2. Copy the speech models with `scripts\push-models.ps1 -Serial $serial`. Kestrel must be installed first. The first run downloads about 760 MB into `%LOCALAPPDATA%\Kestrel\models`, from the addresses in `models\manifest.json`: sherpa-onnx's releases on GitHub and Hugging Face, which redirect to their own download servers. It checks each file's SHA-256 hash against the manifest. Then it copies the files that the phone lacks, and replaces those whose size or hash differs, into Kestrel's folder `Android/data/dev.kestrel/files/models`; on the first run, these are about 740 MB. Kestrel checks them against the same hashes. Kestrel creates that folder when it starts, so the first run after an install may open Kestrel on the phone; open the checklist again to see step 2's new state. Uninstalling Kestrel deletes the models from the phone. With `-Kokoro`, the script also copies the optional Kokoro voice, about 354 MB more, and Kokoro's int8 model, 114 MB more, which only a voice device test loads until the A71 session has compared the two models; then you can choose Kokoro on the page "Voice and speech". The first time that Kestrel turns on with Kokoro, it measures how fast Kokoro speaks on the phone; where Kokoro needs longer to say a sentence than the sentence lasts, Piper speaks instead, and the page says so. A tap on Kokoro on the page, also while it is chosen, makes Kestrel measure it again the next time that Kestrel turns on.
3. Turn on Kestrel's accessibility service. The step's button opens Android's accessibility settings. When Android lists the service as on but does not run it, for example after "Stop app", the step asks you to turn it off and on again. When the service goes off while Kestrel runs, for example because you turned it off, a notification says so until the service is on again, and a tap on it opens Android's accessibility settings.
4. Allow the microphone and notifications. The step's button asks Android for both permissions. After you refuse twice, Android no longer asks, and the button opens Kestrel's app settings instead.
5. Allow unrestricted battery use. The step's button opens Kestrel's app settings, where the battery setting is. While Kestrel's battery use is Restricted, the step shows a warning, because Android then stops listening in the background. On a Samsung phone, also add Kestrel to "Never sleeping apps" in the battery settings; the step names it only there.
6. Optionally, make Kestrel the default digital assistant, so that the assistant gesture, such as a long press of Home or the side key, starts Kestrel and lets you say a task. Android does not let an app ask for this role, so the step's button opens Android's default apps, where you pick Kestrel as the digital assistant app.
7. Optionally, let Kestrel answer and decline calls. The step's button asks Android for the permissions to read the phone state and to answer calls. Kestrel reads no phone number and no call log.
8. Sign in to an AI provider and choose the models. This step comes with Kestrel's provider settings.
9. Optionally, turn off Voice Access, so that it and Kestrel do not react to the same words. While Voice Access is on, the step's button opens Android's accessibility settings, and the checklist warns while both are on.

The settings app also has these pages:

- **Listening and activation:** what Kestrel does when you unlock the phone (resume the mode from before, always start listening, or stay off), a pause after 30 s without speech, the commands during a call ("Kestrel, hang up", "Kestrel, mute" and "Kestrel, speaker", which count only with the name first, because the other person's voice can come through the speaker; Kestrel transcribes only what starts with its name, so nothing of the call's conversation, and when it misses the name, you say the command again), the earbud microphone, and whether the accessibility service, the shortcut, the button and the assistant role start Kestrel (the tile too, which Android does not report), with a button that opens Android's default apps. Each choice counts at once, also when you leave the page right after it.
- **Safety:** test mode, which is on until you turn it off. While it is on, Kestrel's agent and routines will send and share only to Telegram's Saved Messages, WhatsApp's Message yourself, Viber's My Notes and your own email address, and they will make no calls (design spec, section 12.7). Your own instant commands are not limited. Keep test mode on while you test Kestrel. The agent comes later, so in this version test mode changes nothing.
- **Activity log** and **Network log:** what Kestrel did, and every request that it sent, encrypted and kept for 7 days. *Export both logs* writes both logs to a JSON file that you choose, which is the only way the logs leave the phone. *Delete history* wipes both logs after you confirm.
- **Voice and speech:** the voice, Piper or Kokoro (when `push-models.ps1 -Kokoro` copied it), and the speed from 0.8 to 1.4. *Try it* speaks a sentence with the choice on the page; while Kestrel listens with that voice and speed, its voice session speaks the sentence, so that no second copy of the voice is loaded. A new voice or speed counts from the next time that Kestrel turns on; when Kokoro does not load, for example because its files are missing, Piper speaks, and the page says so.
- **Instant commands:** "Require verbs", which makes a name alone, such as "Save", do nothing, so that only "tap Save" taps it, and whether numbers go on all elements or only on those without a name; below them, the list of what you can say, which "What can I say?" opens. Each choice counts from the next command.
- **About:** Kestrel's version, the Android version, whether each speech model is ready (the optional Kokoro voice may be "not on the phone"), and the licence texts.

## Instant commands

While Kestrel listens, you drive the screen by voice without Kestrel's name, as with Voice Access (design spec, section 9 and Appendix A). Say the name of a button to tap it, such as "Send" or "tap Send"; "long press Send" holds it. "Show numbers" puts a number on every element, and then "tap 5", or just "5", taps that element; "hide numbers" removes them. When the numbers change while you say one, Kestrel says "The numbers changed. Say it again.", because the number may name another element by now. "Show labels" shows the name that Kestrel uses for each element, "What is 5?" says the name and the kind of element 5, and "show commands for Send" says what you can do with it. "Show grid" puts numbered squares over the screen for places without an element, "more squares" and "fewer squares" change their size, and "hide grid" removes them. When Kestrel stops listening, because you pause it, a call comes or it turns off, it removes the numbers, the labels and the grid, because only your voice removes them otherwise. You can also scroll ("scroll down", "scroll to bottom", "scroll down on Messages"), swipe ("swipe up", "swipe left on 5", "swipe forwards", "swipe from the left edge"), pinch ("pinch out"), drag ("drag 5 to 9", or "drag 5" and then the place when Kestrel asks "Drag it where?"), check and uncheck ("check Remember me", "switch off"), expand, collapse and dismiss, also notifications in the shade, and move sliders one step ("increment 4", "decrement 4"). A name that you say exactly acts at once when no other element has it, whatever near misses the screen also shows; when two or more elements have that name, Kestrel shows numbers on them only and asks "Which one?". When only a near miss fits, Kestrel acts when the miss is clear, such as "setting" for "Settings", and otherwise asks "Which one?" with its one number, as a confirmation. Answer with the number alone, such as "2", "number 2" or "tap 2": an answer such as "long press 2" ends the question with "Say only the number.", and a number that comes just after the question has ended, within 10 s, does nothing; then say the command again. When nothing matches, it says that it can't find it and shows numbers on every element, so that you can say the number next. A name alone, without a verb, taps only when it clearly names one element: it never asks "Which one?", and it never takes a name that only sounds like what you said, as a command with a verb such as "tap" may. Kestrel ignores other speech without a word, because it may be meant for someone else. "Again" repeats the last command, and "stop" or "cancel" cancels a command while it runs or asks, as a touch does while it asks; while nothing runs, "stop" and "cancel" tap a button with that name. A command that you say while another one runs is dropped, and the feedback bar says "Still busy with the last command." "What can I say?" opens the list of commands on the settings page "Instant commands" and says a short summary.

Before each utterance, Kestrel gives the speech recogniser the names on the screen and a few rare words of the commands, so that it writes them as the screen does. It reads the names from its newest picture of the screen, which it keeps current while it listens; it never uses a password field or what you typed into a field.

The device tests of the instant commands run only through `scripts\command-test.ps1 -Serial $serial`, on the emulator; every other run, such as `connected-test.ps1` above, skips them. The script refuses phones, because the tests change the device's state: Wi-Fi and Bluetooth, the volumes and the ringer mode, Quick Settings' tiles, the lock screen, users, contacts, the call log, screenshots and permissions, and their calls. It ends a call that a test left active, through Android, because Android keeps a call that the emulator's console drops. It puts all of these back at the end, also after a failure or Ctrl+C, except Kestrel's microphone and notification permissions, which stay granted, as after `voice-test.ps1`, because revoking a permission ends Kestrel's process. The text tests also change the clipboard, which the emulator shares with your computer, and put back what it held themselves. The script does not put back Kestrel's own settings: a run leaves Kestrel off, with the default options of the instant commands. It ends with exit code 1 when a test was skipped or something could not be put back. `-Class TouchCommandsTest` runs one class, and `-Class TouchCommandsTest#longPressByLabel` one test.

You can dictate and edit text in any text field, also in Compose apps and on web pages. "Start editing", or "start editing Message" for a field by its name, taps a field and turns dictation on, and so does a field that has the focus: what you say that is not a command is typed at the cursor, with the punctuation that you say ("hello comma how are you question mark" types "Hello, how are you?"), and "capital p one two three" types "P123". Kestrel types only the punctuation that you say. "Type X" types X even when it is a command, as in "type delete"; a button's name alone, such as "Send", is typed too, and "tap Send" taps the button. "Stop editing" turns dictation off for that field and hides the keyboard. You can move the cursor ("go to the end", "move after tomorrow", "left three characters", "right two words"), select ("select tomorrow", "select the next two words", "select all", "unselect"), delete ("delete", which deletes the selection or the word before the cursor, "delete three words", "delete from hello to world", "delete all"), insert ("insert very before nice"), replace ("replace Monday with Tuesday"), change the case ("capitalize paris", "uppercase nasa") and "format email". "Undo" and "redo" take back and redo Kestrel's own edits while the field still shows them, "new line" starts a line in a field with more than one line, "copy", "cut" and "paste" use the clipboard, "show keyboard" and "hide keyboard" do what they say, "show password" shows a password field's text so that you can check it, and "search for coffee" types into the search field and searches. While a password field has the focus, the feedback bar shows "Typing in a password field." instead of what Kestrel heard. Without a field that has the focus, "delete", "copy" and the other one-word commands tap a button with that name.

You can also drive the phone itself: "go back", "go home", "show notifications", "show Quick Settings", "show recent apps", "show previous app", "lock screen", "turn off device" (the power menu), "take a screenshot", "open apps", and "circle to search" where the phone offers it. "Open Chrome" opens an app by its name; "open work Gmail" opens the app of the work profile, from Android 15 on. "Turn on Wi-Fi" and "turn off Bluetooth" switch the radios. "Volume up", "turn the alarm volume down", "mute", "unmute the ringer" and "silence", which puts the phone on vibrate, change the sound, and "media play" and "media pause" reach the player that played last. "Zoom in" magnifies the screen, "pan left" or "scroll left" moves the magnified area, "zoom out" goes one step back, and "stop magnification" ends it. "Call 064 123 4567" or "call Ana" (also "call Ana mobile") opens your phone app with the number, says whom it calls and counts down 4 seconds on the feedback bar before it presses Call; say "cancel" or touch the screen to stop it, and the number stays in the phone app. For a short number, a code with `*` or `#`, or a contact's number with letters, Kestrel only opens the phone app, and you tap Call yourself. Before anything that may call an emergency number, such as "call 112", an "Emergency" or "SOS" button, the phone app's Call button while its number field shows such a number, a short number or one that Kestrel can't read, or anything in a phone app's screen that shows an emergency number, such as a call-history row "112", Kestrel asks you to say "yes, call"; anything else stops it. In a phone app's screen where Kestrel finds no number field to read, such as the list of calls, every command that acts on that screen asks for "yes, call". Where Kestrel reads a text field of the screen (the number field or a search box) and no element shows the emergency number as a whole number, it does not see the controls that call a stored emergency number (a favourite or a call-history row that shows a name, a speed-dial key). It also does not see the Contacts app's page of a contact, "emergency" and "SOS" in other languages than English, or an app's own emergency feature outside the phone app. The first "call [name]" asks for access to your contacts, which Kestrel reads only on the phone. "Copy this phone number" copies a phone number from the screen.

The voice corpus also has the instant commands, with the labels that the screen would show for some of them in `corpus\scenes.txt`; `scripts\voice-eval.ps1` prints the share of them that lead to the correct action, and `-NoLabels` measures it without the screen's labels and the command words. `scripts\a71-commands.ps1 -Serial $serial` takes you through the checks of the instant commands on the Galaxy A71, and through your recordings of the 160 lines of the voice corpus that are marked for you, in about 100 to 125 minutes, of which about 90 to 115 need you; it comes first in the sitting with `scripts\a71-session.ps1`, described above; `-DryRun` tries it on the emulator without you.
